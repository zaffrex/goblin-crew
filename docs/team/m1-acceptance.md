## 왜 따로 적나

M1 판정은 두 가지를 본다. **(가) 끝까지 돌아가는가**와 **(나) 재미있는가**. (가)는 에이전트가 판정할 수 있지만 (나)는 사람만 할 수 있다. 그리고 에이전트는 브라우저를 손으로 누를 수 없다. 그래서 누가 무엇을 어떻게 확인하는지 미리 정해 둔다.

## 판정 1: 끝까지 돌아가는가 (에이전트)

**방법: 배포 URL을 headless Chrome에서 열고, 실제 입력 이벤트로 `solution`을 재생한다.** 단위 테스트(`step` 함수)만으로는 안 된다. 히트 박스, 입력 처리, 말풍선이 정답 클릭을 가리는 문제는 실제 빌드에서만 보인다.

- 도구: `scripts/playtest/` (PM이 만든다. 화면 데이터 형식은 ADR-0065로 정해졌다. 별도 PR). Chrome DevTools Protocol로 마우스 클릭과 터치 탭을 보내고, 행동마다 스크린샷을 남긴다. 클릭 좌표는 화면 JSON의 핫스팟·서는 자리에서 계산한다. 엔진 내부 함수를 직접 부르지 않는다.
- 뷰포트 2개: 데스크톱 1280×720(마우스), 모바일 **844×390 가로**(터치). ADR-0007 결정 1(세로는 회전 안내)과 결정 6(1.44배, 터치 8px 여유)이 가로 기준이기 때문이다.
- **터치 재생은 "탭 2번"이다.** 첫 탭은 선택, 같은 대상을 다시 탭해야 실행된다(ADR-0007 결정 5, ADR-0004 결정 5). 데스크톱처럼 한 번만 탭하면 A1이 거짓 실패한다.

### 판정 2 시작 조건 (그림 붙은 뒤, 사장님 결정 2026-11-16)

사장님이 판정 2를 세 사람 그림과 화면 1 배경이 붙은 뒤에 하기로 정했다([기록](../decisions/2026-11-16-acceptance-2-after-art.md), #142). 그림 PR은 히트 박스(#46)·그리기 순서·연출 길이(busy)를 바꾸므로 판정 1 결과를 그대로 믿지 않는다. 아래가 모두 채워지면 PM이 **그 실행에서 바로** 다시 요청한다.

1. #142 하위 작업이 모두 머지되고 main `deploy`가 성공했다.
2. 배포본에서 `replay.ts --require-art`를 처음부터 다시 돌려 **A1~A4 ✅, A6② ✅, A7 ✅(임시 그림 0개)** 가 나온다. A7은 재생이 지나간 자세만 세므로(`scripts/playtest/README.md`), 실패 경로 자세는 **자세 장부 테스트**(`tests/art/screen-poses.test.ts`)로 본다. 이 테스트는 화면의 모든 도달 가능한 상태 × 모든 행동을 진짜 `step`으로 돌려 캐릭터가 받을 수 있는 자세를 모으고 시트 `anims`와 대조한다. 그 파일의 `MISSING` 목록이 **비어 있어야** 한다(11/16 12:56 기준 17개, Luna 대조표 #142와 같음). 자세 PR은 그림을 넣으면서 그 줄을 지운다.
3. ADR-0007 읽기 규칙 검사(흑백에서 만질 수 있는 것·세 사람 구별, 캐릭터와 바닥 명도 차 30 이상)를 화면 아트 PR에서 통과했다.
4. PM이 데스크톱·모바일 스크린샷에서 두 가지를 직접 본다: 클릭 영역이 커진 캐릭터(#46)가 뒤 핫스팟 클릭을 뺏지 않는다(A1이 통과하면 정답 경로는 확인된 것이고, 여기서는 정답 밖 핫스팟), 말풍선·▼가 그림 머리 위에 뜬다.
5. 바구니 착지(#157 2b, PR #173)를 재생 스크린샷에서 PM이 본다: 고리에서 내려온 사람이 바구니 안 (160, 235)에 서고, 포개진 둘의 위아래가 화면 JSON move 순서와 맞는다. 클리어 컷(L32, #174)이 떠 있는 동안에도 그리기 순서가 그대로다(두 PR이 만나는 지점인데 테스트가 없다. 지금 정답 경로에선 클리어 직전 쭉이가 고리에 있어 안 만난다).
6. #176(고리 기절 시 바구니→바닥 튐): 판정 2 재생 경로에 "고리에서 기절"이 나오면 #176이 머지돼 있어야 한다. 안 나오면 #176에 "재생 경로에 없음"을 적고 M2로 넘긴다. 사장님이 정답 밖에서 고리 쪽을 맞힐 수 있으니 경로에 없어도 6번 질문 답에서 따로 본다.

- 요청 글은 처음 요청(`#goblin-ceo` 11/16)과 같은 형식이되 "그림은 임시 실루엣" 문장을 빼고, 처음 요청 뒤 바뀐 것(그림, 클릭 영역)을 한 줄로 적는다. 질문 6개는 그대로 쓴다.
- 판정 1을 다시 돌려 A1~A4 중 하나라도 실패하면 판정 1과 같은 규칙으로 p0 버그 이슈를 열고 멈춘다.

- **질문은 플레이 뒤에 읽히게 한다.** 질문 문구 자체가 대상 이름이나 상태를 알려 주면 공략이 되기 때문이다.
  - 요청 글: 배포 URL, "힌트 없이 해 보시고, 막히면 막힌 채로 알려 주세요". 공략은 보내지 않는다.
  - 질문: 같은 글의 **스레드 답글**에 "다 하신 뒤 열어 보세요" 머리말을 달아 따로 올린다. 맨 앞에 "0. 플레이 전에 ADR-0003 예시 해법이 기억나셨나요?"를 둔다. 요청 글에 넣으면 플레이 전에 해법을 떠올리게 하거나 찾아보게 만들 수 있어서 플레이 뒤로 뺐다.
- 사장님 시간을 아끼려고 질문은 6개만 한다. 답이 짧아도 된다. 질문에 화면 속 대상 이름(빨래, 바구니, 고리 등)이나 상태(매달림 등)를 쓰지 않는다.
- 사장님이 ADR-0003 예시 해법(시소 발사 → 고리 → 삑으로 까치 치우기)을 기억하시면 1번(클리어)과 단서 판단은 약한 근거다. 그때는 2~4번·6번 위주로 읽는다.

1. 끝까지 깼나요? 못 깼다면 어디서 멈췄나요?
2. 웃긴 순간이 있었나요? 정답과 상관없어 보이는 것도 눌러 봤나요?
3. 짜증 난 순간, 또는 대사가 답을 너무 일찍 알려 준 순간이 있었나요?
4. 위쪽 게이지(보송 게이지)가 줄어드는 걸 봤나요? 봤다면 신경 쓰였나요?
5. 이 화면이 4개 더 있으면 해 보고 싶나요?
6. 시킨 것과 다른 일이 일어나서 "어? 왜?" 싶었던 순간이 있었나요? 버그 같았나요, 웃겼나요?

질문과 관찰의 연결: 1번 = ADR-0018 조건 (1)(유지 상태를 잊고 헤맴), 2번 = 재미 체크리스트 C1(장난감 핫스팟, `magpie_nest.md` "M1 판정에서 볼 것"), 3번 = ADR-0018 조건 (3)(힌트 ②가 너무 이름), 4번 = 조건 (2)(게이지 무시), 6번 = ADR-0065 새 리스크 (1)(손 놓기, `approach` 자동 걷기 순서).

- **L22 단서(#118, PR #120) 읽는 법**: 묵직이 × 고리 기본 반응 "…높다. / 누굴 날려 볼까."는 첫 탭에 "날리다"를 말해서 쭉이 쪽 L10b("위로 올려 줘")보다 세다. 3번 답에 이 대사가 나오거나 "묵직이로 고리를 눌러 보고 바로 풀었다"는 답이 나오면, 판정 후속으로 L10b 수준 대사(예: "…높다. / 가벼운 애라면.")로 바꾼다. 1번에서 고리 단계에 막혔다는 답이 나오면 지금 대사를 유지한다.

- 기다리는 동안 팀은 판정에 막히지 않는 일(첫 실제 스프라이트, M2 화면 매트릭스, #77)을 한다. 화면 2~5 **상세 설계**는 사장님 답이 오기 전에 시작하지 않는다(재설계가 나면 버려지므로).

## 리스크

- **자동 재생은 "사람이 깰 수 있나"를 증명하지 않는다.** 정답을 아는 스크립트는 단서가 약해도 깬다. 그래서 단서·재미 판단은 판정 2에만 맡긴다. 사장님 답이 늦으면 M1이 닫히지 않는다. 그래도 M1 날짜 때문에 판정 2를 건너뛰지 않는다(사장님 방침: 일정보다 디테일 품질).
- 재생 도구를 만드는 시간이 M1 임계 경로에 들어갈 수 있다. #65 머지 직후 시작해서 #68과 병렬로 만든다. 도구가 늦으면 대안은 headless 스크린샷 + `step` 리플레이 테스트지만, 이 경우 A1은 "조건부 통과"로 적는다.
- 피험자가 사실상 사장님 한 명이다. 한 사람 감상으로 퍼즐 원칙(ADR)을 바꾸지 않는다. 원칙 변경은 M2 화면에서 같은 관찰이 다시 나올 때 한다. **반대로 화면 단위 수정(단서 보강, 대사, 게이지 효과 크기 같은 L0)은 한 사람 관찰로도 바로 한다.**
- 사장님이 정답을 이미 알 수 있다. ADR-0003 예시 퍼즐에 화면 1 해법이 그대로 적혀 있고, 사장님도 #15 논의를 보셨다. 그래서 플레이 뒤 질문 0번으로 기억 여부를 묻고, 기억하시면 판정 2를 웃김·짜증·게이지 위주로 읽는다(위 "판정 2").
