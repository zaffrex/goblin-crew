| 안 | 내용 | 장점 | 약점 |

### 화면 줄 (`laundromat`, `park_fountain`)
Luna 순서: `laundromat` 설계 → `park_fountain` 설계 → `laundromat` 그림 → `park_fountain` 그림.

1. **두 화면 상세 설계를 먼저 연달아** 쓴다(Luna). 설계마다 **회색 배치 스케치**(1배, 서는 자리와 걷기 줄. `magpie_nest`의 `magpie_nest-layout.mjs`·#149 같은 것, 화면당 1~2h)를 넣는다. #71 체크리스트 결과 + Theo·PM 종이 플레이. #77의 X4(되찾는 것이 처음부터 보이는가)도 여기서 본다. 그래야 Luna가 그림을 그리는 동안 Theo가 두 화면 엔진 일을 할 수 있다.
   - 회색 배치를 넣는 이유: #226 뒤로 `validate`가 서는 자리 좌표를 검사해서, 배치 없이 쓴 JSON은 그림을 그릴 때 다시 고쳐야 한다. `magpie_nest`에서 그림이 붙은 뒤 터진 문제(#203, #219, #176·#215)는 대부분 위치·크기 문제였다.
2. 화면 JSON + `validate`·BFS 통과(Luna, 리뷰 Theo). 시작 조건: 그 화면 설계 머지.
3. 새 장치 엔진 일(셔터 용수철, 분수 물 켜고 끄기 등)(Theo). 시작 조건: 그 화면 JSON 머지.
4. 배경·물건 → 화면 자세(Luna). 시작 조건: 그 화면 설계 머지. `laundromat`부터.
   - 그림 단계에서 1배 가독성 때문에 설계를 조금 고쳐야 하면(특히 설계 뒤 하루 넘게 지나 그리는 `park_fountain`), **그 그림 PR 안에서 L0로 고치고 BFS·자세 장부를 다시 돌린다.** 퍼즐 해법이 바뀌면 L0가 아니라 설계 PR로 돌아간다.
5. 배포본 replay `--require-art` 종료 코드 0 + smoke 콘솔 에러 0(PM이 돌린다).

## 6. 플래닝에서 물을 것

- **Q1 (Luna)**: 미리 답 받음(#232 리뷰): 공용 리액션 5칸 약 4~5h, 화면별 추정은 3절 표. Theo가 넘겨받을 그림은 분수 물줄기(효과 레이어). 플래닝에서는 `park_fountain` 줄이는 안 ①②를 할지만 정한다.
- **Q2 (Theo)**: 여러 화면 연결에 엔진 계약(ADR-0065) 변경이 필요한지. 필요하면 L2라 ADR이 먼저다. 분수 물줄기를 효과 레이어로 맡을 수 있는지(Q1 ②).
- **Q3 (Ben)**: 세이브 내보내기/가져오기 UI까지 M2에 넣을지, `checkpoint`만 넣을지. 반대 담당으로 A안의 가장 약한 고리도 공격해 달라.
- **Q4 (Sam)**: BFS CI를 붙이면 Actions 시간이 얼마나 느는지(공개 저장소라 0원인지 다시 확인), 화면이 늘 때 배포 용량.
- **Q5 (모두)**: A안 3화면이 끝난 뒤 `dog_yard`·`rooftop_gap`을 붙일 조건. PM 제안은 "사장님 M2 플레이에서 질문 5에 예".
