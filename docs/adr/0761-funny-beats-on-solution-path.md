# ADR-0761: 정답 길 위의 웃긴 박자 (ADR-0018에 원칙 추가)

- 상태: 승인됨 (2026-11-22, PM Noah. PR #784 머지, Luna·Ben ✅)
- 날짜: 2026-11-22
- 작성자: **[PM Noah]**
- 리뷰어: **[디자이너 Luna]**(ADR-0018 원 작성자, 문장·숫자), **[BE Ben]**(반대 담당, 검사 범위)
- 관련: 이슈 #761, M2 플래닝 #230 회의록 `docs/meetings/2026-11-22-m2-planning.md` 안건 1, #257(진마씨 M1 플레이), #603 5회차, #765·PR #780(클리어 연출 건너뛰기), PR #779(U10), #601·#781(Mia 3회차, 27.1초), #67(검사), ADR-0018, ADR-0422, `#goblin-meeting` 11/22 M2 플래닝 스레드

## 배경 (Context)
진마씨는 화면 1(`magpie_nest`)을 한 번도 안 틀리고 깼고 "웃긴 순간이 별로 없었다"고 했다(#257). 지금 웃음은 거의 다 **실패 쪽**(공용 실패 리액션, F3 힌트 대사)에 있다. 그래서 잘 푸는 사람일수록 덜 웃는다. ADR-0018에는 실패 반응 규칙(F2, R2)과 "성공 순간은 고유 애니메이션"(R4)은 있지만, **성공 쪽에 웃음이 있어야 한다**는 규칙이 없다.

Luna가 정답 길로만 갔을 때 웃긴 장면을 셌다(반만 웃기면 0.5, M2 플래닝 1라운드):

| 화면 | 정답 길 웃음 | 메모 |
|---|---|---|
| `magpie_nest` (당시 배포본) | 1.5 | 클리어 반전 컷 U10이 그림 없이 빠져 있었음. PR #779로 들어감 |
| `park_fountain` | 4 | 4개 중 3개가 클리어 연출에 몰림 |
| `laundromat` (설계) | 2~3 | |

**H1을 지금 화면에 대 본 결과**(PR #784 Luna 리뷰, U10 반영 뒤). 두 화면이 못 지킨다:

| 화면 | 정답 길 박자 | 합 | 클리어 연출 밖 | H1 |
|---|---|---|---|---|
| `magpie_nest` (U10 뒤) | 규칙 4 `magpie_squeak_down` 까치 내려와 노려봄 0.5, 시소 발사 1, U10 반전 1 | **2.5** | 1.5 | ❌ 합 부족 |
| `park_fountain` | 4 (3개가 클리어 연출 안) | 4 | 1 | ✅ |
| `laundromat` (설계) | `clear_hang` 1, 빈 열쇠 걸이 → 까치 1 | 2 | **0** | ❌ 밖 0 |

U10만으로는 `magpie_nest`가 H1을 지키지 못한다. 고치는 법은 결정 1절 "지금 화면 대조"에 있다.

화면마다 지켜야 할 규칙이라 퍼즐 설계 원칙이고 L2다. M2 화면 3개가 모두 이 규칙을 지키는 것이 M2 완료 조건이다(회의록 "M2 범위와 완료 조건").

**회의 뒤에 잰 숫자.** 회의에서 클리어 연출 "처음 볼 때 카드 전까지 4초 안"을 정했다. 근거는 "컷 글 2초 + U10 약 2~2.5초"였다. 그런데 정답 규칙 하나 안에는 컷 앞에 정답 행동 anim과 대사도 들어 있다. 실제로 재 보니(#761 Theo 코멘트, PR #780·#779 측정, 정답 행동 입력부터 카드까지, 말풍선을 넘기지 않음):

| 화면 | 처음 볼 때 | 내용 |
|---|---|---|
| `magpie_nest` (U10 전) | 6.0초 | 뻗기 1.0 + 대사 2.5 + 아이템·놓기 0.5 + 컷 글 2.0 |
| `magpie_nest` (U10 뒤, PR #779) | 약 7.2초 | Theo frames 측정. Luna PR 본문의 "약 3.75초"는 재는 시작점이 다르다(아래 결정 3에서 시작점을 정한다) |
| `park_fountain` | 27.1초 | 말풍선 4개 약 12.2초 + anim·fx 13개 + 컷 글 2.0. Mia 3회차 데스크톱이 "끝났는지 모르겠다"(#601) |

4초는 지금 있는 두 화면 모두 못 지킨다. 숫자를 고쳐야 한다.

## 고려한 선택지 (Options)
회의 1라운드의 A~D다(섞어도 됨).

### A. 정답 길 위에 웃음 (성공 반응 자체를 엉뚱하게)
- 장점: 안 틀려도 보인다. 진마씨처럼 잘 푸는 사람에게 닿는 유일한 안이다. `park_fountain`은 이미 이렇게 짰고, `magpie_nest`는 U10(+4칸)을 붙였지만 그것만으로는 합 2.5다(배경 둘째 표).
- 단점: 성공인지 실패인지 헷갈릴 수 있다(#603: 그림 없는 `…あれ？`가 "왜 클리어?"로 읽힘). 클리어 연출이 길어진다(`park_fountain` 27.1초).

### B. 틀리고 싶게 만들기 (그럴듯한 오답 대상 + 제일 웃긴 반응)
- 장점: F2(실패가 이유를 보여 줌)와 맞는다.
- 단점: R1 칸을 먹는다. 상태를 바꾸는 오답이면 BFS 그래프가 늘고 막다른 상태(S3) 위험이 생긴다(Ben).

### C. 가만히 있어도 웃김 (캐릭터 대기 장난)
- 장점: 플레이와 무관하게 보인다.
- 단점: 잘 푸는 사람은 기다리지 않아서 안건을 못 푼다(Theo·Luna). 캐릭터 대기 장난은 엔진 4~6h.

### D. 첫 실패를 설계로 보장
- 장점: 누구나 실패 반응을 한 번은 본다.
- 단점: "속았다" 짜증 위험. `laundromat`은 정답이 2단계라 첫 실패 보장이 곧 정답을 숨기는 일이 된다(Luna).

## 결정 (Decision)
**A를 원칙으로, B는 권장, C는 데이터로 되는 것만, D는 하지 않는다.** ADR-0018에 아래 절(7절 "웃음")을 더한다. ADR-0018의 다른 절은 바꾸지 않는다.

### 1. 정답 길의 웃음 (A, 원칙)
- **H1. 커밋된 정답 경로(`solution`)의 웃긴 박자 합이 3 이상이고, 클리어 연출 밖 박자 합이 1 이상이다.** 반만 웃긴 박자는 0.5로 센다(0.5짜리를 1개로 치지 않는다). 그래서 클리어 연출 밖에는 온전히 웃긴 박자 하나, 또는 반만 웃긴 박자 둘이 있어야 한다. 주 아하 단계는 담백해도 된다. 아하는 깔끔하게 보이는 게 먼저다.
  - **클리어 연출**은 `solution`의 마지막 step(클리어 규칙)이 내는 anim/say/fx 전부다. 그 앞 step은 모두 "클리어 연출 밖"이다(Ben). 클리어 컷은 데이터에 따로 없고 클리어 규칙 배열 안에 있어서 이렇게 가른다.
  - **2행동 화면(튜토리얼)도 예외를 두지 않는다.** 진마씨 불평은 "안 틀리고 깨면 안 웃기다"였다. 짧은 화면일수록 안 틀리고 깨기 쉬워서, 예외를 두면 이 규칙이 막으려는 경우가 그대로 남는다(Luna).
- **H2. 성공이 먼저 보이고, 엉뚱함은 그다음 박자다**(C8 성공 리듬). 화면이 바뀌어 성공이 보인 뒤에 엉뚱한 한 박자를 붙인다. 엉뚱함이 성공보다 먼저 오면 실패로 읽힌다(#603).
- **지금 화면 대조와 고칠 것**(배경 둘째 표, 둘 다 새 칸 0, 담당 Luna, 이슈는 이 ADR 머지 뒤 Luna가 연다):
  - `magpie_nest` 2.5 → 규칙 4 `magpie_squeak_down`을 0.5에서 1로 올린다. 까치가 내려와 노려볼 때 삑삑이가 공용 움찔 자세로 반응하고, L05를 그 반응에 맞게 바꾼다(공용 자세 + 대사, H4 ②와 같은 순서). 중간 성공이라 H5 1.5초 안이다. 클리어 연출 쪽은 H6 여유가 0.8초뿐이라 대사를 더 넣지 않는다.
  - `laundromat` 밖 0 → 정답 1번 `latch_pull_open`에 박자를 붙인다. 빛줄(성공)이 먼저 보이고, 풀린 걸쇠 핀이 튕겨 ノビー 이마에 `コツン`(fx만) → `latch_open` 허세 대사(H2 순서). 2 + 1 = 3, 밖 1. 중간 성공이라 늘어나는 길이는 H5 1.5초 안이다.
- **H3. 웃긴 박자는 사람이 판정한다.** Luna가 화면 설계 문서에 "정답 길 웃긴 박자" 표를 쓰고, Mia QA 보고의 "웃겼던 순간"과 진마씨 플레이로 확인한다. 화면 JSON에 "웃김" 표시를 넣지 않는다(퍼즐 타입이 바뀌면 코어 PR이 되고, 기계는 웃김을 못 센다).

### 2. 오답 미끼 (B, 권장)
- **H4. 미끼 대상은 필수가 아니다.** 넣을 때는 ① 퍼즐 상태와 게이지를 바꾸지 않는 연출만 한다(Ben). 미끼는 그 대상의 **폴백(`fallbacks.<hotspot>`)으로 만든다.** 폴백은 타입상(`HotspotFallbackDef`) 게이지만 바꿀 수 있어 퍼즐 상태를 못 바꾼다. 미끼 폴백에는 `do.gauge`를 넣지 않는다. 규칙(`rules`)으로 만들어야 할 때만 `rule.id`를 `decoy.`로 시작한다(예: `decoy.dryer_3`, `ID_RE`가 이미 점을 허용해 타입 변경 없음). ② 공용 자세 + `say.text` 배열 변형(0칸)을 먼저 쓰고, 그래도 안 웃길 때만 고유 칸을 그린다(Theo). 고유 칸은 R1(ADR-0422) 예산 안에서 센다.
- 지금 적용: `laundromat`의 `dryer_3`·`soap_vending`(규칙 0개, 폴백만, PR #771). `park_fountain`은 새 칸을 그리지 않고, 0칸 변형도 진마씨 스테이지 2 플레이 뒤에 본다.

### 3. 길이 (회의 숫자 고침)
**재는 법(모든 숫자 공통)**: 처음 볼 때, 걷기가 끝나고 **정답 규칙의 첫 연출이 시작될 때부터** 다음 상태가 될 때까지(클리어면 카드가 뜰 때까지), 말풍선을 넘기지 않고 잰다. 걷기는 직전 자리에 따라 달라서 뺀다. 도구는 replay 또는 `frames.ts --every 150`(시각이 찍혀서 더 정확하다). 화면 JSON PR 본문에 숫자를 적는다.
- 배경 표 `magpie_nest` 7.2초(Theo, 뻗기 시작부터)가 이 기준이다. PR #779 본문의 약 3.75초는 L01 말풍선이 끝난 뒤 컷 구간만 잰 숫자다.
- **H5. 중간 성공**(클리어가 아닌 정답 단계)에 붙는 엉뚱함은 담백한 판보다 **1.5초 안**에서 늘린다. 두 번째부터는 짧은 판을 쓴다(#765 2/2 anim n번째 변형).
- **H6. 클리어 연출은 처음 볼 때 카드까지 8초 안**이다. 두 번째부터는 탭 한 번에 카드로 넘어간다(PR #780, 이미 머지).
  - 회의의 "4초 안"을 고친다. 4초는 정답 행동·대사를 빼고 센 숫자였다(위 배경 표).
  - 8초 근거: U10이 붙은 `magpie_nest`가 약 7.2초다. 진마씨는 U10 전 6.0초 판을 불평 없이 봤다. Mia가 "끝났나?"라고 한 것은 27.1초 판이다. 그 사이에서 지금 화면 1이 통과하는 가장 짧은 숫자로 잡고, 플레이에서 다시 본다.
  - **예외: `park_fountain`은 12초 안**(#781 PM 결정). 4박자 컷이 이미 그려져 있고 주 웃음(물 다시 솟음)이 그 안에 있어서 8초로 자르면 웃음을 잘라야 한다. 새 화면에는 예외를 주지 않는다.

### 4. 기다림 (C)과 첫 실패 (D)
- **H7. 대기 웃음은 데이터로 되는 것만**: `onEnter` 개그, 물건 `loop`. 캐릭터끼리 대기 장난(엔진 4~6h)은 하지 않는다.
- D(첫 실패를 설계로 보장)는 하지 않는다.

### 5. 검사 (#67, 코어 PR)
- `solution` 재생과 BFS `shortestPath` 재생에서 고유 `anim`/`say` 수를 센다. 리포트 줄 이름은 **`정답 길 반응`**(클리어 연출 밖/안을 나눠 적는다, H1 정의), **`오답 반응`**(정답 길 밖 상태의 반응, 분모는 게이지 제외 상태 키 `foldedCount` 기준)으로 둔다. R1 `uniqueReactions`(정적 집계)는 그대로 두고 이름을 섞지 않는다(Ben). `common.*`는 따로 센다. **규칙이 하나도 없는 핫스팟(장난감)의 폴백**과 `decoy.` 규칙을 미끼로 본다. 미끼 폴백에 `do.gauge`가 있거나 `decoy.` 규칙이 flags/items/at(캐릭터 자리 제외)·게이지를 바꾸면 경고한다(H4 ①). 규칙이 있는 핫스팟의 폴백(예: `latch` 실패)은 미끼로 세지 않는다. 재생 값은 `StepResult`의 `events`·`ruleId`로 세므로 타입은 바꾸지 않는다. 나중에 장난감 핫스팟에 규칙이 하나라도 생기면 그 폴백은 미끼 분류에서 빠지므로, 그때 미끼는 `decoy.` 접두어 규칙으로 옮긴다(Ben·PM). `note`에 미끼라고 적힌 핫스팟이 미끼로 안 잡히면 경고만 낸다(실패 아님, #67 구현).
- 구현은 `src/core/puzzle/check.ts` 코어 PR이다. #781처럼 화면 데이터가 급하면 M2 화면 3 설계 전까지 미뤄도 된다.
- **검사는 "반응이 있다"까지만 본다. 웃김 판정은 H3대로 사람이 한다.** 숫자는 리포트 한 줄과 PR 본문에만 쓰고 CI를 실패시키지 않는다(Ben: 숫자가 목표가 되면 반응을 억지로 늘린다).
- 길이(H5·H6)는 지금 검사에 넣지 않는다. replay로 재서 PR 본문에 적는다. 같은 숫자를 두 번 넘기는 화면이 나오면 검사에 넣을지 다시 본다.

## 반대 의견 (Dissent)
- **Luna(PR #784 리뷰)**: "H1을 지금 화면에 대면 두 화면이 탈락하는데 ADR에 없다", "0.5를 1개로 치면 규칙이 너무 쉽게 통과된다" → 배경 둘째 표, H1 세는 법, 지금 화면 대조, 2행동 예외 없음으로 받아들였다.
- **Ben(PR #784 반대 담당 리뷰)**: 리포트 이름이 R1과 겹침, 클리어 연출 밖의 기계 정의, 미끼를 가릴 표시 없음, 오답 반응 분모 → 5절과 H1·H4에 넣었다.
- **Luna(PR #784 재리뷰)**: `laundromat` 미끼는 `rules`가 아니라 `fallbacks`에 있어 `decoy.` 접두어만으로는 못 찾음 → H4 ①·5절을 "폴백 미끼 + 규칙 0개 핫스팟" 기준으로 고쳤다.
- **Ben(회의 반대 담당)**: "B의 그럴듯한 오답 대상이 다수안의 가장 약한 고리. 상태를 바꾸면 S3·피해 경로 경고가 새로 난다." → H4 ①로 받아들였다. "검사 숫자가 규칙을 대신하는 것처럼 읽힐 수 있다" → 5절에 명시했다.
- **Luna(2라운드)**: "1.5초를 클리어 컷에도 걸면 U10이 첫날부터 규칙을 어긴다." → H5(중간 성공)와 H6(클리어)을 나눴다.
- **Theo(2라운드)**: "건너뛰기가 있어도 처음 보는 사람은 끝까지 본다. 클리어에도 상한을 두자(4초)." → 상한은 받아들였고, 숫자는 측정 뒤 8초로 고쳤다. **이 고침은 회의 뒤 PM 판단이라 리뷰에서 반박 받는다.**
