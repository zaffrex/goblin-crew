# ADR-0005: MVP는 서버 없이 localStorage 세이브로 간다

- 상태: 제안됨
- 날짜: 2026-11-15
- 작성자: **[BE Ben]**
- 리뷰어: (FE Theo, Infra Sam 요청 예정)
- 관련: 이슈 #6

## 배경 (Context)
M2(퍼즐 3~5개 + 세이브 + 모바일 터치)에 서버가 필요한지 결정한다. 제약: 월 비용 0원(비용 발생 시 L3), 팀 운영 부담 최소, 개인정보 수집 최소. 현재 계획된 기능은 진행 상황 저장뿐이고 계정·리더보드 요구는 없다.

## 고려한 선택지 (Options)
### A. 서버 없음 + localStorage 세이브 (+ 파일 내보내기/가져오기)
- 장점: 월 0원, 운영·보안·개인정보 부담 없음, 오프라인 동작, 구현 1~2일.
- 단점: 기기 간 동기화 없음, 브라우저 데이터 삭제 시 소실, 플레이 통계 수집 불가. iOS Safari는 장기 미사용 시 저장소를 정리할 수 있음.
- 월 비용: **0원**

### B. 서버리스 (Cloudflare Workers+KV/D1 등 무료 티어) 클라우드 세이브·통계
- 장점: 기기 간 세이브, 어느 퍼즐에서 막히는지 익명 통계.
- 단점: 익명 ID/토큰 설계, 레이트 리밋, 남용 방지 필요. 무료 티어 초과 시 비용 발생(→ L3). 개인정보 고려 필요. 운영 대상이 늘어남.
- 월 비용: 무료 티어 내 **0원**, 초과 시 발생 (한도 모니터링 필요)

### C. 자체 API 서버 + DB
- 장점: 자유도 최대.
- 단점: 호스팅 비용(대개 유료), 운영·백업·보안 부담. MVP 대비 과함.
- 월 비용: **0원 초과 가능성 높음** → 추천 시 L3

## 결정 (Decision)
**A를 채택한다.** 근거: M2 요구가 "세이브"뿐이며 localStorage로 충족된다. 서버가 가치를 주는 기능(동기화, 통계)은 MVP 성공 조건이 아니다. 저장 접근은 `SaveStore` 인터페이스 뒤에 두어 나중에 B로 교체할 수 있게 한다.

### 세이브 데이터 초안 (JSON, 키: `goblincrew.save.v1`)
```json
{
  "version": 1,
  "updatedAt": "ISO-8601",
  "progress": { "unlockedScreens": ["s01"], "solvedScreens": [], "currentScreen": "s01" },
  "screens": { "s01": { "flags": {}, "inventory": [], "characterPos": {} } },
  "settings": { "volume": 0.8, "textSpeed": "normal" }
}
```
- `version` 필수. 로드 시 버전별 마이그레이션 함수 체인(`v1→v2…`)을 적용하고, 알 수 없는 상위 버전·파싱 실패 시 덮어쓰지 않고 백업 키로 보관 후 새 세이브로 시작한다.
- 화면 내부 상태는 퍼즐 단위 체크포인트(화면 입장 시점 + 해결 시점)만 저장 — 중간 상태 저장은 FE와 협의 후 확장.
- 개인정보 없음. 크기 목표 < 50KB.
- 내보내기/가져오기(JSON 파일)를 M2에 포함해 소실 위험을 완화한다.

## 반대 의견 (Dissent)
아직 없음. 가장 강한 반론: "나중에 통계가 필요해지면 늦다." 반박: 통계는 B로 추가 가능하고(아래), MVP 데모 단계에서는 소수 플레이테스트 피드백(수동)으로 충분하다. 반론이 현실화되면 재검토한다.

## 결과 (Consequences)
- 좋아짐: 0원, 단순함, 보안·개인정보 이슈 없음.
- 나빠짐: 기기 간 이동 불가, 소실 위험(내보내기로 완화), 통계 없음.
- 리스크: 세이브 스키마가 퍼즐 설계에 따라 변경됨 → `version`+마이그레이션 테스트로 대응.
- **나중에 서버를 붙일 때 바뀌는 범위**: `SaveStore`에 원격 구현체 추가, 익명 ID 발급 엔드포인트, 로컬↔원격 병합 규칙(`updatedAt` 최신 우선, 충돌 시 사용자 선택). 세이브 JSON 형식은 그대로 업로드 가능하므로 데이터 마이그레이션 불필요. B 이상은 비용 가능성이 있으면 L3로 올린다.
- 재검토 조건: 플레이테스트에서 기기 간 이동/통계 요구가 반복되거나 리더보드 기능이 기획될 때.
