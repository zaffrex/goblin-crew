## 배경 (Context)

진마씨가 세 판(`magpie_nest` → `park_fountain` → `laundromat`)을 하고 답했다(`#goblin-ceo` 2026-11-28): 세 번째 판 적당, 웃긴 곳 없음, "왜 이렇게 클리어했는지 잘 모르겠다. 퍼즐 요소가 전혀 없다", "처음의 건조기가 왜 이렇게 동작하는지 이해 못 했다". 그리고 "눈에 보이는 아이템1을 조작해서 변화, 다음에 아이템2를 조작해서 1이랑 결합해서 아이템3으로 퍼즐을 푸는 요소가 전혀 없고 너무 단순해."

설계 회의 중 진마씨가 방향을 바로잡았다(`#goblin-meeting` 2026-11-28):
- **"인벤토리의 이야기는 아니었어."** 기준은 물건을 주머니에 모으는 UI가 아니라 **화면 속 물건이 그 자리에서 바뀌고 다른 물건과 만나는 횟수**다.
- 장르 대표작 1편의 구조 설명: **한 화면 완결**, 화면 속 물건 **5~6개**, 물건은 **한 번에 하나만** 든다, 틀린 작동은 **웃긴 반응 + 체력 감소**.
- "한명만 잡기가 좋아 아니면 각각 능력은 하나씩" → 물건을 집고 드는 건 **쭉이만**, 묵직이는 무게, 삑삑이는 소리([결정 기록](../decisions/2026-11-28-one-picker-one-ability-each.md)). ADR-0003의 "공통 동작(줍기·건네기·쓰기)은 셋 다" 줄이 이 기록으로 바뀌었다.

숫자로 봐도 맞다(조사 #1033 3절, #1035 3~4절).

| | 원작 1~3편 12화면 (중앙) | 우리 3화면 |
|---|---|---|
| 물건을 쓰는 단계 | 12/12화면, 4.5번 | 0 |
| 물건 변화 / 결합이 있는 화면 | 9/12 / 8/12 (둘 다 5/12) | 0 / 0 |
| 정답 행동 수 | 12 | 3~4 |
| 의존 깊이 | 7 | 2~3 |
| 한 층 폭 ≥2 | 10/12 | 2/3 |
| 같은 변화 규칙을 두 번 쓰기 | 4/12 (Theo 재셈, #1035 리뷰) | 0 |
| "왜"를 성질 한 문장으로 설명 | 6/12 | 0/3 |

원인은 ADR-0018이다. 1절이 퍼즐을 **능력 매트릭스**(어떤 능력이 몇 화면에서 필수인가)로만 정의했고, 정답 길 모양은 M6(경고) 하나뿐이었다. 그래서 "맞는 특기를 맞는 곳에 한 번" × 3~4가 매트릭스를 통과했다. 그 뒤 ADR-0422·0761과 화면 설계는 반응과 웃음만 고쳤고 퍼즐 몸통은 한 번도 보지 않았다. 설계 쪽 원인은 #1033 3-2절에 적었다: 고리마다 그 화면만의 버릇(스누즈 관리인, 역회전 건조기)을 새로 발명해서, 놀랍지만 앞으로 추론할 수 없었다.

퍼즐 설계 원칙이라 L2다. 다음 화면 설계와 Theo 손 1칸 코어 작업이 이 결정에 걸려 있다.

제약: 사용량(#117)이 빠듯하다. 조작은 "얼굴 고르기 → 물건 누르기 한 번"(진마씨 11/18)이고 메뉴는 다시 넣지 않는다. 물건 상태 변화는 엔진에 이미 있다(플래그 + 그림 `states[].when` + 핫스팟 `variants`, Theo 1라운드). 새로 드는 건 쭉이 손 1칸뿐이다. 휴대폰은 아직 판정 전이다(#935).

## 고려한 선택지 (Options)

### A. 물건 사슬이 몸통, 능력은 고리를 여는 손 (추천)
일반 화면의 정답 길을 "화면 속 물건이 그 자리에서 바뀌고 → 다른 물건과 만나 → 새 물건·상태가 되어 → 막힌 곳을 푼다" 사슬로 만들고, 셀 수 있는 숫자로 검사한다. 물건을 옮겨야 하는 고리만 쭉이가 집어 든다(1개). 묵직이·삑삑이의 특기는 물건의 성질을 바꾸는 손이 된다.
- 장점: 진마씨 문장 모양과 1편 구조 설명 그대로다. 원작 분포(물건 사용 12/12)와 맞는다. "성질 두 개로 한 문장"이 진마씨 ③ "왜"에 바로 답한다. 물건 상태 변화는 엔진 0h이고, 손 1칸 모형 화면도 BFS 285~5,685노드·≤2.5s다(Theo 1라운드).
- 단점: 손 1칸 코어(`hands`·`holds`·`pick`·`put`)와 입력이 새로 든다(Theo 추측 9~13h). 그림이 첫 화면에 늘어난다(Luna, 5절). 빨래방을 다시 짜면 역회전 줄 약 47칸이 정답 길에서 빠질 수 있다. 화면 하나의 행동이 2~3배가 된다. M2가 늦어진다.

### B. 능력 퍼즐 그대로 + 화면당 물건 단계 1개
- 장점: 싸다. 손 없이 장치 하나의 상태 변화만 더하면 된다.
- 단점: 원작 최소치(사용 ≥1, 중앙 4.5)에도 못 미친다. 행동 4~5, 깊이 3이면 "너무 단순해"가 그대로 남는다. 진마씨가 짚은 변화·결합이 없다.

### C. 능력을 아이템으로 바꿈 (특기 대신 도구)
- 장점: 사슬이 가장 순수해진다.
- 단점: 세 사람 구분이 사라진다. ADR-0003 세계관과 "능력의 엉뚱한 사용"(우리 기준의 앞 반쪽)을 버린다. 진마씨 "각각 능력은 하나씩"과도 어긋난다. 게임 콘셉트 근본 변경에 가까워 L3 위험이 있다.

## 결정 (Decision)

**A를 채택한다.** 숫자는 시작값이다. 첫 적용 화면(빨래방 다시 짜기)의 Mia 블라인드와 진마씨 플레이 뒤 다시 본다.

### 1. 퍼즐의 정의 (ADR-0018 1절 첫 문단을 바꾼다)
- **화면 퍼즐 = 화면 속 물건 사슬.** 물건은 기본으로 **화면 안 그 자리에서** 성질이 바뀌고, 다른 물건·장치와 만나 새 물건·상태가 되고, 막힌 곳을 푼다. 사슬은 그 화면 안에서 닫힌다(한 화면 완결).
- **능력은 한 사람에 하나씩, 고리를 여는 손이다.** 쭉이 = 집기·들기(1개)·내려놓기·쓰기, 묵직이 = 무게, 삑삑이 = 소리([결정 기록](../decisions/2026-11-28-one-picker-one-ability-each.md)). 특기는 정답 버튼이 아니라 물건이나 장치의 성질을 바꾸는 수단이다. ADR-0018 M1~M5(능력 필수·비율)는 그대로 두고, 이 ADR의 C1~C9가 그 위에 얹힌다.
- **고리 종류** (설계 문서 고리 표와 검사가 같은 말을 쓴다):

| 고리 | 모양 | 데이터에서 셈 (Theo 리뷰에서 확인) | 클릭 수(C6) | 깊이(C6) |
|---|---|---|---|---|
| 집기 | 빈손 쭉이 × 들 물건 → 쭉이 손에 | 효과 `pick`이 있는 규칙 | 셈 | 안 셈 (운반) |
| 내려놓기 | 든 채로 쭉이 얼굴 → 쭉이 발밑 | 효과 `put`이 있는 규칙 | 셈 | 안 셈 (운반) |
| 변화 | 물건 + 능력 또는 장치 → 그 자리에서 성질이 바뀜 | 물건 상태 플래그(그 물건 그림 `states[].when`·핫스팟 `variants`가 보는 플래그)를 바꾸는 규칙 | 셈 | 셈 |
| 결합 | 든 물건 × 화면 속 물건·장치, 또는 장치 안에 재료 둘 이상 → 새 물건·상태 | 조건 `holds` X + 대상 Y의 상태 조건 → 새 상태 플래그. 장치 안: 재료마다 넣기 플래그 → 모으는 규칙이 플래그 전부를 봄 | 셈 | 셈 |
| 쓰기 | 물건(든 것 또는 그 자리에서 바뀐 것) → 막힌 곳이 풀림 | 조건 `holds` 또는 물건 상태 플래그 + 막힌 곳 대상 → 목표 쪽 플래그 | 셈 | 셈 |
| 내주기 | 물건 → NPC·동물이 움직임 | 쓰기의 한 종류로 센다 | 셈 | 셈 |

- 한 행동에 고리 종류가 둘 붙을 수 있다(예: 든 물건을 장치에 넣기 = 쓰기 + 결합 재료). 행동 수는 행동 하나로 센다(Theo #1035 리뷰 2번).
- **손에서 물건 둘 합치기는 없다.** 손이 1칸이라서다. 결합은 든 물건 × 화면 속 물건·장치, 또는 장치 안에서 한다.

"일반 화면"은 튜토리얼이 아닌 화면이다. 지금 `magpie_nest`만 튜토리얼이다.

- C1·C2·C7(≤4)은 구조라서 실패로 둔다. C4(a)(b)·C5·C6은 원작에서 가져온 추정치이거나 아직 셀 키가 없어서 경고로 시작한다. 경고가 나면 PR에 이유를 적고 머지할 수 있다(ADR-0018 1절 CI 구분과 같은 방식).
- **옮겨 가는 동안의 예외**: C1·C2·C7 검사는 Theo 손 1칸 코어 PR에서 들어간다. 그때 아직 이 ADR대로 다시 짜지 않은 화면(`magpie_nest`·`park_fountain`·지금 `laundromat`)은 검사 예외 목록에 두고, 다시 짠 화면부터 뺀다. 예외 목록은 비어 가기만 한다.
- **"왜" 기준은 원작보다 높다.** 원작도 6/12화면만 성질 한 문장으로 설명된다. 진마씨 ③ 때문에 우리는 C3을 모든 고리에 건다. 대신 우리 특기(장대·쿵·소리)는 물리라서 마법류보다 맞추기 쉽다(#1035 4절 3번).

### 3. 막다른 상태와 세이브 (Ben 반대 반영)
- **S3는 그대로이고 물건 소모를 포함한다.** 지금도 `bfs.ts` `deadEnds`가 "도달한 모든 상태에서 클리어에 닿나"를 보고 `check.ts` `reportErrors`에서 실패다. 재료를 넣어 없앤 뒤 막히는 상태, 틀린 결합이 재료를 먹은 상태도 여기서 잡힌다(Theo 1라운드).
- **노드 수를 화면 리포트에 늘 적는다.** 들 물건 하나에 노드 ×3.7, 올라설 자리 하나에 ×4다(Theo 실측). `maxStates` 100,000 한도에 걸리면 S3 판정 불가 = 실패가 된다(ADR-0096 7). 화면 JSON PR은 리포트의 노드 수를 PR 본문에 적고, **5만(한도의 절반)**을 넘으면 설계를 줄일지 Theo와 본다. 들 물건 4개 모형(21,120)의 두 배 여유다.
- **CI 시간**: 틀린 작동마다 게이지를 깎으면 노드가 ×5다. 받아들이고, Theo가 손 1칸 코어 PR에서 BFS `actions`를 7동사 전부가 아니라 한 번 누르기로 낼 수 있는 행동만으로 줄인다(5.7k노드 화면 2.5s → 1.15s, 노드 수 같음).
- **화면 안 사슬 상태와 쭉이 손은 저장하지 않는다.** 새로고침하거나 이어 하면 그 화면 입구에서 다시 시작한다. 화면 하나가 8~12클릭이라 다시 해도 1~2분이다. 세이브 스키마(`src/core/save/schema.ts`)는 바꾸지 않는다.
- **화면 사이로 물건을 넘기지 않는다.** 진마씨 "한 화면 완결"이다. 앞 화면 물건이 다음 화면 재료가 되는 설계는 금지한다. 그래서 세이브 v2도 필요 없다. 넣고 싶어지면 새 ADR + Ben 세이브 v2다.

### 4. 입력 (Theo 1라운드 표 + 한 줄, 조작 한 번 원칙 유지)
| 고른 사람·손 | 누른 곳 | 결과 |
|---|---|---|
| 빈손 쭉이 | 들 수 있는 물건 | 집기 |
| 빈손 쭉이 | 장치·자리 | 지금처럼 장대 능력 |
| 쭉이가 아닌 사람 | 들 수 있는 물건 | **그 사람 능력이 그 물건에 나간다**(같은 물건이 묵직이에겐 밟을 것, 삑삑이에겐 울릴 것) |
| 쭉이가 아닌 사람 | 장치·자리 | 지금처럼 내 능력 |
| 든 채로 쭉이 | 아무 대상 | 든 물건 쓰기(장대 능력은 안 나감) |
| 든 채로 쭉이 | 쭉이 얼굴 | 내려놓기, 쭉이 발밑에 놓인다(지금 "아무 일 없음" 자리라 새 버튼 0) |
| 든 채로 쭉이 | 바닥 | 든 채로 걷기 |

- 쭉이가 든 채로 다른 사람을 골라도 손은 그대로다. 그 사람은 위 표의 "쭉이가 아닌 사람" 줄대로 움직인다.
- 무엇이 나갈지는 호버·터치 첫 탭 라벨로 보인다(`{target}に{item}を使う`가 이미 있다).
- 든 물건은 쭉이 머리 위 칸(그림 형식 16절 `anchor`)에 그린다. 손 포즈 그림을 물건마다 그리지 않는다.
- 코어: `PuzzleState.hands` + 조건 `holds` + 효과 `pick`/`put`(`src/core/puzzle/` 코어 PR, 리뷰 2명). 노드 수는 플래그로 적는 것과 같다(Theo). BFS `actions` 줄이기를 같은 PR에 넣는다(3절).

### 5. 그림 비용 (숫자는 Luna가 이 ADR 리뷰에서 다시 낸다)
- Luna 1라운드(11/28)는 진마씨 정정 전이라 인벤토리 기준이었다. 이번에 빠지는 것: 인벤토리 틀·고른 칸·커서 3칸, 묵직이 `hold` 2칸(묵직이는 들지 않는다), 물건 아이콘 16×16 몫(화면당 5칸, 시간 2칸 값).
- 남는 것: 공용 성질 효과 시트(물방울·반짝·김 × 2칸 = 6칸). 성질은 물건마다 상태 그림을 따로 그리지 않고 효과로 얹는다. 쭉이 `hold` 2칸은 이미 있다.
- 새로 드는 것: 쭉이 머리 위 든 물건 표시. 화면 속 물건 그림을 다시 쓰는지, 작은 그림이 따로 드는지 Luna가 정한다.
- 화면당: 변화 순간·쓰기 순간 anim, 쓴 뒤 상태 칸, 틀린 조합(공용 흔들기 + 대사면 0). Luna 1라운드 화면당 14~24칸에서 아이콘 몫을 뺀 값이 시작점이다.
- 성질 차이(젖음·마름 등)는 그림 한 단계라 잘 안 읽힌다. 효과 시트와 호버 라벨 낱말로 같이 보인다(C3).
- ADR-0422 R1 상한은 세 화면 다 이미 넘었다(50·54·84 > 48). R1' 상한을 다시 정하는 건 이 ADR에 넣지 않고 Luna가 ADR-0422 개정으로 숫자를 낸다(회고 #2 A1 #1028과 같은 때).

### 6. 첫 적용과 순서
1. 이 ADR 머지.
2. 나란히: Theo 손 1칸 코어(`hands`·`holds`·`pick`·`put` + C1·C2·C7 검사 + 노드 수 리포트 + BFS `actions` 줄이기, 추측 9~13h) ∥ Kai 빨래방 다시 짜기 설계 문서 + 특기 성질 공통 표(C4).
3. Luna 칸 수 리뷰 → 그림(추측 8~11h, 5절 재셈으로 바뀜) → JSON·검사 → Mia 블라인드 → 진마씨.
- **첫 적용 화면 = 빨래방 다시 짜기(PM 결정).** 근거: 진마씨가 마지막에 본 판이고 ③ "건조기가 왜"에 같은 방으로 답한다. 방·세탁기·건조기·자판기를 다들 아는 성질(적신다·말린다·내준다)대로 쓰면 장치 쪽 새 칸이 거의 0이다(Luna). 대가: 역회전 → 흡입 줄 약 47칸(≈15h)이 정답 길에서 빠질 수 있다. 반응·실패 쪽 재사용(예: 덕트 혹 `lump_travel`을 "덕트로 물건을 보낸다"로)은 Kai·Luna가 설계에서 본다.
- `magpie_nest`(튜토리얼, C1 집기 ≥1)와 `park_fountain`은 빨래방이 진마씨께 통한 뒤 다시 짠다. 그때까지 2절 예외 목록에 있다.
- 설계 PR 리뷰어는 #1035 6절 "닮음 검사 목록"과 겹치는지 본다. 사슬 모양·한 명만 드는 규칙은 장르 관습이라 쓰고, 원작의 구체 조합은 쓰지 않는다(CLAUDE.md IP 가드레일).

### 7. ADR-0761(웃긴 박자)과의 관계
- 웃긴 박자 H1~H7은 그대로 둔다. 박자 자리는 사슬이 정해진 뒤 다시 센다. 웃음은 변화·결합 **결과 칸**(물건이 우스꽝스럽게 바뀌는 순간)과 틀린 조합(C8)에 놓는 것을 기본으로 한다.

## 반대 의견 (Dissent)
- **Ben (반대 담당, 회의 1라운드)**: "되돌릴 수 없는 막다른 상태(소프트락)와 세이브. 지금 BFS 검사(M6)는 시작점→클리어 경로 존재만 봄." → 앞 문장의 사실은 다르다. S3 검사(`deadEnds`)가 이미 모든 도달 상태를 보고 CI 실패다. 대신 그 지적에서 진짜 위험(상태 수 증가 → 판정 불가 = 실패)을 3절 노드 수 보고 줄로 받았다. 세이브 쪽 "화면 중간 상태 저장 여부 결정"은 그대로 받아 "저장 안 함, 화면 입구 재시작, 화면 사이 물건 없음(한 화면 완결)"으로 적었다.
- **PM (회의 안건) "인벤토리 UI가 조작 한 번 결정과 부딪힌다"**, **Luna (회의 1라운드) "아이템 칸 24px × 3, 휴대폰 탭 33px"** → 진마씨 정정 "인벤토리의 이야기는 아니었어"로 인벤토리 줄이 빠져 둘 다 사라졌다. 남은 건 쭉이 손 1칸이고 4절 표대로 새 버튼 0, 든 물건은 머리 위 칸 표시다.
- **PM (회의 정리) "쭉이가 모든 사슬에 끼어 혼자 바쁘다"** → 받아들인다. C4 (a) 쭉이 행동 ≤60%, (b) 묵직이·삑삑이 물건 상태 변화 고리 각 ≥1로 검사한다. 첫 화면에서 쭉이 행동이 절반을 넘거나 "쭉이만 움직인다"는 말이 나오면 [결정 기록](../decisions/2026-11-28-one-picker-one-ability-each.md) 다시 볼 조건대로 한다.
- **Theo (회의 1라운드) "든 게 이김이라 줍기·내려놓기가 정답 길에 섞인다"** → C6을 둘로 나눴다. 클릭 수(8~12)는 집기·내려놓기를 세고, 깊이(≥5)는 상태가 바뀌는 고리만 센다. 손 수고와 퍼즐 깊이를 따로 본다.
- **Kai (회의 1라운드) "휴대폰에서 탭을 바꿨다 오면 리로드되어 화면 처음부터라 짜증 날 수 있다"** → 리스크로 남긴다. 3절대로 저장은 안 하고, 첫 적용 화면 Mia 휴대폰 회차에서 본다.
- 가장 강한 반론 (B 쪽): "엔진·그림이 드는 A보다, 물건 단계 1개만 넣고 진마씨께 빨리 다시 보여 주자." 답: 원작에서 물건 사용이 가장 적은 화면도 1번이고 중앙은 4.5번이다. 한 단계만 넣으면 행동 4~5, 깊이 3이라 진마씨가 이미 "너무 단순해"라고 한 숫자 안에 남는다. 진마씨께 같은 답을 두 번 받는 비용이 엔진 작업보다 크다.

## 결과 (Consequences)
- 좋아지는 것: 퍼즐 몸통을 셀 수 있게 된다(C1·C2·C7 CI). 묵직이·삑삑이 성질 표가 화면 사이에 공통이라 플레이어가 앞 화면에서 배운 것으로 다음 화면을 추론한다(C4·C5). "왜"가 설계 문서 한 문장과 보이는 결과로 리뷰된다(C3). 세 사람이 능력 하나씩이라 "누구에게 무엇을 시키나"가 사슬의 고리가 된다.
- 나빠지는 것: Theo 손 1칸 코어 추측 9~13h, 첫 화면 그림 추측 8~11h(5절 재셈으로 바뀜), 빨래방을 다시 짜면 약 47칸(≈15h)이 정답 길에서 빠질 수 있음. 틀린 작동 게이지로 BFS 노드 ×5, CI 시간 증가(BFS `actions` 줄이기로 상쇄). 화면 하나의 행동이 2~3배가 되어 Mia·진마씨 플레이 시간도 늘어난다.
- **M2 숫자**: ADR 머지 → (Theo 손 1칸 코어 9~13h ∥ Kai 빨래방 설계) → Luna 그림 ≈ 8~11h → JSON·검사 → Mia 블라인드 → 진마씨 요청. 하루 실행량이 지금 같으면 진마씨 요청은 **12/2~12/3 무렵**(추측). 12/4 주간 리포트에서 PM이 다시 맞춘다.
- 새 리스크: (1) 물건이 다 보이면 "다 눌러 보기"로 풀릴 수 있다 → C3·C7·C8, Mia 오답 시도 기준(아래). (2) 성질 한 문장(C3)이 사람 검사라 설계자가 스스로 통과시킬 수 있다 → Mia 블라인드 "누르기 전 예상" 줄로 판정한다. (3) 원작 숫자를 기준으로 삼아 모양이 원작에 가까워질 수 있다 → #1035 6절 닮음 검사. (4) 쭉이 쏠림 → C4. (5) 휴대폰 리로드면 화면 처음부터.
- 다시 검토할 조건: 첫 적용 화면에서 (1) 진마씨가 다시 "단순하다"고 하면 C1·C6 하한을 올린다. (2) Mia가 무차별 대입으로 풀면(오답 시도가 정답 클릭의 3배를 넘으면) C7을 줄이거나 C8을 강화한다. (3) 노드 수가 5만을 넘는 화면이 나오면 BFS 상태 키(ADR-0096)나 C7 ≤4를 다시 본다. (4) 쭉이 행동이 정답 길의 절반을 넘거나 "쭉이만 움직인다"는 말이 나오면 쭉이만 집기 기록을 다시 본다. (5) 화면 사이 물건을 넣고 싶어지면 새 ADR.
