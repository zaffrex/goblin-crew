# ADR-0096: BFS 상태 키에 게이지를 넣는다 (ADR-0065 8절의 노드·리셋 간선·피해 간선 재호출 대체)

- 상태: 승인됨 (2026-11-15, PM Noah. PR #97 머지. 상태 줄은 #435에서 일괄 변경)
- 날짜: 2026-11-15
- 작성자: **[BE Ben]**
- 리뷰어: (요청) **[디자이너 Luna]** 퍼즐 원칙(ADR-0018) 정합, **[FE Theo]** `step` 계약·반대 담당, **[PM Noah]** 승인
- 관련: 이슈 #96, #67, PR #92(리뷰 스레드), ADR-0065 8절, ADR-0018(S3·G2·G3·M6), `src/core/puzzle/step.ts`(`faint` 분기)

## 배경 (Context)
PR #92 리뷰에서 ADR-0065 8절의 구멍 두 개가 나왔다.
1. **무조건 붙는 리셋 간선** (Luna): 다치는 행동을 할 수 없는 곳에 갇힌 진짜 막다른 상태도 "리셋으로 탈출 가능"이 되어 S3를 통과한다. 최단 경로도 리셋을 0행동으로 센다.
2. **`gauge = 1` 재호출** (Ben): "같은 상태에서 피해를 반복할 수 있다"를 전제한다. 피해 행동이 자리·플래그를 바꾸면(예: `dog_yard`의 "울타리 밖으로 밀려남", ADR-0065 9절) 그 상태로 돌아올 수 없어, 리셋 간선을 없애도 존재하지 않는 기절 간선이 남는다.

## 고려한 선택지 (Options)
### A. 리셋 간선 제거 + 피해 간선(`gauge = 1` 재호출)만 유지 (Luna 초안)
- 장점: 노드 수가 늘지 않는다. 변경이 작다.
- 단점: 위 2번 구멍이 남는다. 화면 1의 다치는 실패는 전부 사람을 `yard`로 보내므로 바로 해당된다. 그래프가 `step`과 달라져 S3가 근사치가 된다.

### B. 키에 `gauge`를 넣고 리셋·재호출을 모두 없앤다 (Ben)
- 장점: 그래프가 `step`과 똑같다. 기절은 `step`이 내는 `faint` 이벤트를 그대로 따른다. 구멍을 하나씩 찾아 막을 필요가 없다. ADR-0018 G3(화면 진입 시 게이지 가득, 이월 없음)으로 시작 노드는 `(start, 5)` 하나다.
- 단점: 노드가 최대 `GAUGE_MAX` = 5배. 보고가 게이지별로 반복될 수 있다(아래 보고 규칙으로 해결).

### C. 현 상태 유지 (ADR-0065 8절 그대로)
- 장점: 코드 변경 없음.
- 단점: S3가 거짓 통과를 낸다. 거부.

## 결정 (Decision)
**B를 택한다.** 다음을 정한다.

1. **노드 키** = `PuzzleState` 전체: `at`, 선언 순서 `flags`, 정렬된 `items`, `gauge`. 리셋 간선과 `gauge = 1` 재호출은 삭제한다. 간선은 `step` 결과 그대로다.
2. **클리어 상태는 펼치지 않는다** (S4). `clear` 이벤트가 난 상태는 도달 노드로 세되 후속 간선을 만들지 않는다.
3. **S3 판정**: 퍼즐 상태 하나라도 막다른 **도달한** `(S, g)`가 있으면 실패다(0~`GAUGE_MAX` 전부를 만들어 검사하지 않고 시작 `(start, GAUGE_MAX)`에서 도달한 노드만 본다). `faint` 간선 포함 전체 그래프 기준이다.
4. **보고는 게이지를 접는다**: 키에서 게이지를 뺀 퍼즐 상태 단위로 한 줄. "막힌 게이지 값 목록 + 시작→그 상태 최단 경로 1개". 경로의 `faint` 단계에는 표시를 붙인다. (Luna·PM 요청)
5. **피해 의존 경고** ("자해로만 탈출", Luna·Theo 리뷰 반영): "피해 없는 그래프"를 정의한다. 전체 그래프에서 **게이지가 줄어드는 간선**(`gauge` 이벤트 `delta < 0` 또는 `faint` 이벤트가 있는 간선)을 빼되, **`clear` 이벤트도 있는 간선은 남긴다**(마지막 행동이 다치면서 클리어하는 경우를 거짓 경고로 만들지 않기 위해). 전체 그래프로 도달했고 **전체 그래프로 클리어에 닿는** 퍼즐 상태 S마다, 피해 없는 그래프에서 S가 클리어에 닿는지 본다. 못 닿으면 경고(실패 아님)하고 경로를 함께 출력한다. 피해 없는 그래프에서는 게이지가 변하지 않으므로(회복 효과 `gauge: +1`이 생기면 재확인) 경고는 저절로 게이지 없는 키 단위가 되고, 게이지 1에서만 거짓 경고가 나는 일이 없다. 보고 접기(Theo 재리뷰 실측 반영): 경고된 S마다 "필수 피해 행동" = S에서 클리어까지 피해 간선 수가 최소인 경로(0-1 BFS)에 나오는 피해 간선의 `ruleId` 집합(폴백이면 `대상.동사`)을 구한다. 최소 경로가 여럿이면 행동 열거 순서(결정적)로 고른다. 보고는 BFS 트리(시작에서 처음 발견한 부모) 기준으로 접는다. 부모가 경고됐고 S의 필수 피해 행동이 부모 것의 부분집합이면 접는다(순환 때문에 "선행 경고가 있으면 접기"만 쓰면 전부 접혀 0줄이 된다). 나머지는 한 줄씩: 퍼즐 상태, 시작→S 경로, 필수 피해 행동. 근거: ADR-0018 G1은 게이지를 "다치는 *실패*"에서만 깎는다. 탈출에 피해가 필수면 실패가 필수 단계가 된다. 필수 피해가 의도라면 디자이너가 경고를 확인하고 넘기면 된다(경고는 CI 실패가 아님).
6. **최단 경로·M6·`requiredAbilities`**: 결정 5의 "피해 없는 그래프"에서 `(start, GAUGE_MAX)`부터 센다. 클리어에 못 닿으면(피해 필수 화면) 전체 그래프 최단을 내고 결정 5 경고를 함께 낸다. 피해 간선(기절 포함)을 쓰는 경로가 더 짧으면 "피해 지름길" 경고(기절 지름길 포함). `requiredAbilities` 결과가 전체 그래프와 다르면 둘 다 표시.
7. **`truncated`**: S3 판정 불가로 실패 처리. 결과에 `deadEndsKnown: boolean`을 두고, `truncated`일 때 `deadEnds`는 비우되 `deadEndsKnown = false`. CLI는 이 값이 `false`면 S3를 실패로 찍는다.
8. **`validate.ts`**: `when`의 모르는 키(예: `gauge`)를 실패로 처리하고 테스트로 확인한다. 이제 BFS 전제는 아니지만, 게이지 조건 금지는 ADR-0018 4절 끝 "게이지는 벌이 아니라 리듬"이 근거이며, `when`에 게이지를 허용하면 "일부러 다쳐서 맞추는" 퍼즐이 가능해져 피해 의존을 데이터로 허용하게 되므로 유지한다. 우선순위는 낮다.

### 예상 판정표
| 대상 | 기대 판정 |
|---|---|
| 화면 1 `magpie_nest` | 막다른 상태 0, 최단 4, 기절 의존·지름길 경고 0 |
| #92 장난감 A (지붕에서도 `hurt` 가능) | 실패 아님, **피해 의존 경고** (피해 간선을 빼면 지붕에서 못 내려옴) |
| #92 장난감 B (`hurt`는 `gate`에서만) | **S3 실패**: 지붕 상태의 모든 게이지에서 막힘, 접어서 한 줄 |
| `dog_yard` 류 (피해가 자리를 바꿈) | 피해 후 상태가 다른 노드로 정확히 표현됨. "밀려남"이 유일한 탈출이면 모든 게이지에서 **피해 의존 경고**. `faint`로 시작점 쪽 지름길이 있으면 "피해 지름길" 경고 |

### 상태 수 추정
예시 화면 실측(Theo, `magpie_nest` 픽스처): 접은 상태 61(클리어 7개 포함, 제외 54) → 노드 305(딱 5배), `step` 호출 19,440, 97ms. 아래 약 1,700상태 × 5 ≈ 8,500 → 약 50만 호출은 넉넉한 상한 추정(기존 약 10만 호출 + 피해 행동 재호출 대비 약 5배). `step`은 순수 함수·작은 객체 복제라 CI에서 몇 초 안이다. 도달 상태 10만 경고선은 **게이지 포함 키 기준**으로 그대로 둔다(접은 상태로는 약 2만이므로 CLI 경고에 노드 수와 접은 상태 수를 같이 찍는다)(실화면은 1,700×5 수준이라 여유 큼). 화면이 커져 경고에 걸리면 그때 선을 다시 본다.

## 반대 의견 (Dissent)
가장 강한 반론: "게이지를 키에 넣으면 상태가 5배가 되고, 보고가 5배 길어진다(Luna·PM)." 비용은 몇 초라 감수하고, 보고는 결정 4번으로 접는다.
다른 반론: "게이지 0→`GAUGE_MAX` 복원이 `flags`·`items`를 그대로 두는 것이 G2(벌칙 뒤 복귀) 의도와 같은가?"(PM이 Theo에게 질문). Luna(G2 작성자)와 Theo 둘 다 "같다"고 확인했다(G2 "리셋되는 것은 서는 자리뿐", `finish`는 `at`·`gauge`만 바꿈). 다만 기절이 진행을 잃지 않아 게이지가 약해질 수 있는 위험은 M1 플레이테스트(#86)에서 본다. 이 ADR의 범위 밖.

## 결과 (Consequences)
- 좋아지는 것: S3·최단 경로가 게임 규칙과 같은 함수에서 나온다. 거짓 통과/거짓 기절 간선이 구조적으로 사라진다. 코드가 더 단순해진다(리셋·재호출 로직 삭제).
- 미정: 의도된 필수 피해 경고의 억제 방법(화면 JSON vs 검사기 설정)은 첫 사례가 나올 때 정한다.
- 나빠지는 것: 상태·호출 수 약 5배. `bfs.ts` 키 함수·보고 코드 수정이 필요하다.
- 후속: #67 후속 PR에서 구현(리셋 간선 제거, `faint` 간선 표시, 보고 접기, `deadEndsKnown`, 클리어 비전개). 이 ADR 머지 전에는 #67을 닫거나 BFS를 CI 게이트에 연결하지 않는다. #67 체크리스트를 이 ADR 기준으로 갱신한다.
- `faint` 의미에 버그가 있으면 검사기도 같이 틀린다(`step` 하나를 공유하는 ADR-0065 원칙의 비용). 기절 의미는 `step.test.ts`가 잡는다.
- 재검토 조건: 화면 크기로 상태 수가 경고선을 자주 넘을 때. 첫 화면이 걸리면 게이지를 뺀 투영으로 먼저 거르는 방법을 검토한다(유지 상태가 2개인 M2 `rooftop_gap` 류에서 곱으로 늘 수 있음, Luna).
