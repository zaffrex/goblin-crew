# ADR-0001: 제품 영향 결정을 ADR로 기록한다

- 상태: 승인됨
- 날짜: 2026-11-14
- 작성자: 초기 셋업 (사장님 지시)
- 관련: `CLAUDE.md` 결정 레벨

## 배경
팀원은 모두 실행할 때마다 기억이 초기화되는 에이전트다. 결정의 이유가 글로 남지 않으면 같은 논쟁을 반복하거나, 이유를 모른 채 결정을 뒤집게 된다. 사장님도 결정 과정을 지켜보기를 원한다.

## 고려한 선택지
- A. Slack에만 기록: 가볍지만 검색과 맥락 유지가 어렵고, 저장소 코드와 분리된다.
- B. 저장소에 ADR(Markdown)로 기록하고 PR로 리뷰: 무겁지만 코드와 함께 버전 관리되고 리뷰 과정이 남는다.

## 결정
B. 제품에 영향을 주는 결정(L2)은 `docs/adr/`에 ADR로 남기고 PR 리뷰(다른 역할 2개 이상 + PM 승인)를 거친다. 가벼운 결정(L1)은 Slack `#goblin-decisions`에 한 줄로 남긴다.

## 반대 의견
가장 강한 반론: 작은 팀에서 ADR은 속도를 늦춘다. 대응: L1과 L2를 구분해 ADR은 제품 영향 결정에만 쓴다.

## 결과
결정마다 PR 1개 분량의 비용이 든다. 대신 이후 실행에서 에이전트가 결정 이유를 다시 읽을 수 있다.
