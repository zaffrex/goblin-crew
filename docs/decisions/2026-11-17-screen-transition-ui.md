# 결정: 화면 전환은 클리어 카드 탭 → 0.6초 어두워졌다 밝아짐, 저장은 카드가 뜰 때

- 레벨: L1
- 날짜: 2026-11-17
- 결정자: 디자이너 Luna (제안), 프론트 Theo (구현·리뷰 합의)
- 참여: Luna, Theo, (참고) Ben
- 출처: #230 Q2 Theo 답 리스크 2번("클리어 컷 뒤 탭으로 넘어가는 흐름은 UI라서 `docs/design/ui-interaction.md`에 한 줄 L1 기록이 필요해요"), #230 Q3 Ben 답(화면 입장 시점 스냅샷), #230 Luna 코멘트(게이지 ADR-0018 G3)

## 배경
M2는 화면이 3개 이상이다. 지금 화면 1은 클리어 카드(`ui.clear`, "…화면 1 클리어")에서 끝나고 그 뒤가 없다. Theo의 여러 화면 연결 PR(약 4~5h)과 Ben·Theo의 세이브 연결이 시작되기 전에 전환 흐름, 입력, 저장 시점을 정해 둬야 `main.ts`를 두 번 고치지 않는다.

## 선택지
- A. 클리어 카드 몇 초 뒤 자동으로 다음 화면. 탭이 없다. 대신 휴대폰을 내려놓은 사이에 다음 화면 첫 대사를 놓치고, 푼 화면을 다시 볼 틈이 없다.
- B. 클리어 카드에서 탭하면 짧게 어두워졌다 밝아진다(0.3 + 0.3초). 카드의 처음 0.6초 탭은 무시한다. 구현이 싸고, 터치 2번 탭 실행 뒤의 잘못된 탭을 막는다.
- C. 캐릭터가 출구로 걸어 나가는 전환. 보기는 좋지만 출구 방향, 화면 사이 위치를 화면 설계마다 맞춰야 해서 화면당 비용이 붙는다.

## 결정
**B.** 세부는 [`docs/design/ui-interaction.md` 11절](../design/ui-interaction.md). 핵심만 적는다.
- 카드 글은 화면 번호(`화면 1 클리어`)를 빼고 화면별 결과 문장 `<id>.clearCard` + 공용 `ui.next`(0.6초 뒤 나타남)로 한다. A안에서 `magpie_nest`는 두 번째 화면이라 번호가 틀리게 된다.
- 다음 화면에서 게이지는 가득(ADR-0018 G3), 지금 캐릭터는 유지, 무장은 풀고, 아이템은 비운다.
- **`checkpoint`는 클리어 카드가 뜰 때 다음 화면 id로 쓴다.** 카드에서 새로고침해도 방금 깬 화면을 다시 하지 않는다. Ben의 "화면 입장 시점 스냅샷"과 뜻은 같고 시각만 당긴다.
- 마지막 화면은 재회 컷 → 끝 카드(`ui.end`) → 탭 → 타이틀. 끝 카드에서 "다 깸"을 기록해서 타이틀에 `이어 하기`가 나오지 않는다.

## 반대 의견
가장 강한 반론: "탭 한 번도 흐름을 끊는다. 화면 3개면 자동 전환이 더 매끄럽다." 화면 수가 적어서 탭 비용이 작고, 카드가 F2(실패해도 웃긴 화면을 푼 뒤 쉼표)의 보상 순간이라 B를 골랐다. 판정에서 "카드가 거슬린다"가 나오면 A로 바꾼다. 데이터 변경이 없어서 되돌리기 쉽다.

## 다시 볼 조건
- M2 판정에서 카드를 눌러야 하는 걸 몰랐다(멈춰 있었다)는 관찰이 나오면 `ui.next`를 더 크게 하거나 3초 뒤 깜빡임을 넣는다.
- 화면 사이에 아이템을 넘기는 설계가 나오면(ADR-0065 "다시 검토할 조건 (2)") 11-3절 아이템 줄을 다시 쓴다.
- 화면 중간 저장을 넣으면 11-4절 저장 시점을 다시 본다.
