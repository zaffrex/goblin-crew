# 결정: 바닥에서 행동할 때 대상 앞까지 걸어간 뒤 한다

- 레벨: L1
- 날짜: 2026-11-16
- 결정자: 디자이너 Luna (제안), 프론트 Theo (구현·리뷰 합의)
- 참여: Luna, Theo
- 출처: 로컬 빌드(main `15e9cba`) 실플레이 스크린샷, #68 2부-b, PR #116 Luna 리뷰 메모 1

## 배경
#122로 화면 1이 처음부터 끝까지 돈다. 그런데 바닥에 선 캐릭터는 선 자리에서 그대로 행동한다. 정답 3번(묵직이 쿵 → 쭉이 발사)이 시소에서 약 110px 떨어진 곳에서 일어나고, 규칙 8·15와 장난감 반응도 대상과 떨어져서 나온다. 결과는 맞지만 "왜 저렇게 됐지?"로 읽힌다.

## 선택지
- A. 지금처럼 제자리에서 행동. 구현 0. 대신 화면 1의 가장 큰 아하(발사)가 인과 없이 보인다.
- B. 엔진이 연출용 바닥 안 걷기를 넣는다. 설 곳은 동사와 대상 박스로 계산한다. 퍼즐 상태·데이터 모델은 그대로다.
- C. 핫스팟마다 설 곳 필드(`standX` 등)를 데이터에 넣는다. 정확하지만 ADR-0065 스키마 변경이라 코어 PR + L2다.

## 결정
**B.** 규칙은 `docs/design/ui-interaction.md` 5-1절. `stretch`는 `reachPoint` 아래, `stomp`·`hand`·`item`은 높은 대상이면 아래·바닥 대상이면 가까운 가장자리 옆, `squeak`·`look`·`approach: stay`는 걷지 않는다.

## 반대 의견
- 행동마다 걷기가 붙어 느려진다(화면 1 최장 약 2.8초). → `walk`와 같아서 탭으로 건너뛴다(5절 예외 둘). 지루하다는 관찰이 나오면 #38과 같이 본다.
- 계산 규칙이 안 맞는 화면이 나올 수 있다(예: 대상 바로 아래가 벽). → 그때 C를 L2로 올린다. M2 화면 2 설계에서 먼저 확인한다.

## 다시 볼 조건
- M2 화면 설계에서 계산된 설 곳이 어색한 대상이 2개 이상 나오면 C.
