## 배경
외부 클로즈 베타 도구가 goblin-crew에서 결정 기록이 실제로 다시 쓰이는지 시험하고 싶다고 제안했다. 11/15에 조건 4개를 붙여 M1 뒤 2주 시범으로 합의했고, 11/22 상대가 그날 main(`12ca7db`)에 맞춘 새 패치를 보냈다. 11/16 패치는 폐기했다. 도구 이름과 상세 논의는 상대 요청으로 Slack에만 둔다.

## 선택지
- A. 받지 않는다 (리스크 0 / 실험 기회를 놓친다)
- B. 조건부 2주 시범 (실제 데이터를 얻는다 / 에이전트 실행에 외부 코드가 훅으로 돈다, 구독 사용량이 조금 는다)

## 결정
B. 11/15에 합의한 조건 그대로 간다.
1. main 예외 없음. 기록 파일은 원래 PR 안에 커밋되어 CI·리뷰 게이트·리뷰를 그대로 거친다.
2. 플러그인 소스를 저장소 `.github/beaket/`에 넣고 커밋으로 버전을 고정한다. 그 폴더는 CODEOWNERS(진마씨 승인) 대상이다. 들어오기 전에 Sam이 코드를 읽고 보안 검토한다.
3. **ADR과 `docs/decisions/`가 루트 `decisions/`의 기록보다 우선한다** (`CLAUDE.md`에 명시).
4. 저장소 변수 `BEAKET_ENABLED`가 `"true"`일 때만 켜진다. 2주 뒤 PM 회고에서 유지/철수를 정하고, 철수는 함께 받은 철수 패치로 한 번에 되돌린다.

추가 확인(11/22 새 패치): 라이선스는 시범 뒤 git 기록·fork에 남는 것을 위반으로 보지 않는다. 공개 파일에 들어가는 값은 저장소 소유자 GitHub 이름뿐이다. 번들은 압축되지 않았고 포함 라이브러리(yaml, zod)의 버전·출처가 적혀 있다. QA 실행에는 플러그인을 불러오지 않는다(#516 정답 차단 유지).

켜는 시점: 진마씨가 "Sam 검토 후 내 승인 후 바로 켜자"로 정했다(`#goblin-ceo`, 2026-11-22). PR 두 개가 머지되면 바로 변수를 켠다. PM 추천은 11/26 04:00 사용량 리셋 뒤였다(리셋 때 사용률 87~96% 예상). 그래서 첫 주는 사용량을 status에서 매일 본다.

## 반대 의견
가장 강한 반론(PM, 11/15): 플러그인 훅은 진마씨 구독 토큰과 Slack 토큰이 있는 에이전트 환경에서 돈다. 외부 코드가 그 안에서 실행된다. 소스 고정 + CODEOWNERS + Sam 검토 + 끄는 스위치로 다뤘다. 남는 리스크는 1.1MB 번들을 사람 대신 에이전트가 검토한다는 점이다.
