## 배경
화면 1 배경(#145)이 완성 밀도 샘플(#154)로 사장님 OK를 받았고, Luna가 물건 시트 ③을 그리기 전에 엔진이 읽을 형식을 맞춰야 다시 그리는 일이 없다. ADR-0007 결정 8은 "필드 이름과 파일 형식은 M1 에셋 파이프라인 L1에서 Theo와 정한다"고 넘겼다. 캐릭터 시트 형식은 이미 정했으니(위 기록), 여기서는 **화면 배경과 만질 수 있는 물건**만 정한다.

## 선택지
- A. **배경 한 장 + 물건 시트. 물건은 화면에 제자리로 그리고 빌드가 잘라서 좌표를 넣는다** (Theo 제안). 장점: 그림이 `magpie_nest.json` 좌표를 벗어날 수 없다. 호버 외곽선(ADR-0007 결정 2)을 물건마다 만들 수 있다. 단점: 빌드 스크립트가 자르기·검사를 맡아 커진다.
- B. 배경에 물건까지 다 구워 넣고, 바뀌는 것만 덮어 그린다. 장점: 파일 하나, 빌드 단순. 단점: 투명 경계가 없어 호버 외곽선을 못 만든다. 까치처럼 자리가 바뀌면 배경 쪽 그림을 지울 수 없다. 캐릭터와 앞뒤를 못 정한다.
- C. 물건 시트를 캐릭터 시트처럼 칸 단위로 그리고 좌표를 사람이 적는다. 장점: 캐릭터 시트와 형식이 같다. 단점: 좌표를 두 곳(화면 JSON, 시트)에 적어 어긋날 수 있다. Luna가 칸마다 위치를 계산해야 한다.

## 결정
**A로 한다.** #157 제안에 Luna의 추가 A·B·C와 `loop`를 넣은 것이 v1이다.

### 1. 파일
- 원본: `art/scenes/<화면>.mjs` (지금 `docs/design/screens/magpie_nest-density-sample.mjs`의 그리기 코드를 옮긴다). 질감 붓은 `art/lib/`를 쓴다.
- 출력(`node art/build.mjs`, 커밋): `public/scenes/<화면>-bg.png`(480×270, 불투명 인덱스 PNG), `public/scenes/<화면>-objects.png` + `.json`.
- PNG 형식·팔레트·"다시 만들면 바이트가 같다" 검사는 캐릭터 시트와 같다.

### 2. 배경에는 만질 수 없는 것만
`magpie_nest.json`에서 `box`가 있는 대상(hotspot `magpie`·`nest`·`basket`·`long_johns`, spot `seesaw_left`·`seesaw_right`·`hook`)은 모두 물건 시트로 뺀다. 빨랫대 기둥, 빨랫줄 기둥, 담장, 수건, **시소 받침(세제 통)** 은 배경이다.

### 3. 그리는 쪽은 좌표를 적지 않는다
`.mjs`에서 물건의 그림마다 **480×270 투명 화면에 제자리로** 그린다. 빌드가 불투명 영역을 잘라 시트에 붙이고 `at`(화면 좌표, 왼쪽 위)을 넣는다.

```js
// art/scenes/magpie_nest.mjs (모양)
export const SCENE = {
  id: 'magpie_nest',
  bg(img) { /* 480×270 */ },
  objects: {                                   // 적은 순서 = 뒤 → 앞 (같은 층 안에서)
    nest: {
      draw(img) {},                            // default: 열쇠 있음
      loop: { ms: [1600, 120, 120], frames: [(img) => {}, (img) => {}, (img) => {}] }, // default의 반복(반짝임)
      states: [{ when: { flags: { 'nest.key_taken': true } }, draw(img) {} }],
    },
    magpie: {
      draw(img) {},                            // 둥지 위, 캐릭터 뒤
      loop: { ms: [2500, 150, 300], frames: [/* U8 */] },
      states: [{ when: { flags: { 'magpie.on_ground': true } }, layer: 'front', draw(img) {}, loop: { /* U8 바닥 */ } }],
    },
    long_johns: { draw(img) {} },
    seesaw: { ids: ['seesaw_left', 'seesaw_right'], draw(img) {} }, // 널빤지 한 장, ID 둘
    basket: {
      draw(img) {},                            // 뒤판 + 안쪽
      overlay: { sortY: 236, draw(img) {} },   // 앞판(높이 10px)
    },
    hook: { draw(img) {} },
  },
  anims: {
    'seesaw_right.plank_bounce': { ms: 80, frames: [/* 3장: 오른쪽이 내려감 */] },
    'seesaw_left.plank_bounce': { ms: 80, frames: [/* 3장: 왼쪽이 내려감 */] },
    'magpie.fly_down': { ms: 100, frames: [], layer: 'front' }, // 첫 칸 = 둥지, 마지막 칸 = 바닥 (4-2절)
    'magpie.ruffle': {                         // 둥지 위(기본) / 바닥(갈래) (4-1절)
      ms: [100, 150, 100], frames: [/* 둥지 위 */],
      variants: [{ when: { flags: { 'magpie.on_ground': true } }, ms: [100, 150, 100], frames: [/* 바닥 */], layer: 'front' }],
    },
  },
};
```

### 4. 멈춘 모습은 상태에서, 움직임은 이벤트에서
- **멈춘 모습**: `when`이 맞는 첫 state, 없으면 `default`. `when` 문법과 "첫 일치"는 핫스팟 `variants`와 같다(`src/core/interact.ts` `hotspotBox`).
- **반복(`loop`)**: state·`default`에 선택 필드 `loop: { ms: number | number[], frames }`. `ms`가 배열이면 프레임별 시간이다(길게 멈췄다 짧게 움직이는 반짝임·U8 까치 대기). 반복끼리 박자는 맞추지 않는다. `loop`가 없으면 그림 1장이다.
  - 개정 3: 처음 기록은 "시계는 화면 전체가 하나"였다. 그러면 `fly_down`이 바닥 smug로 끝나도 바로 다음 칸이 화면 시계 위치에 따라 `flick`/`puff`일 수 있었다(약 17%, #237). 그래서 **그 물건의 anim이 끝나거나 멈춘 모습이 바뀐 때부터 0으로 센다**(`src/core/sceneArt.ts` `loopStarts`). 물건끼리 박자를 맞추는 게 아니라 한 물건 안에서 이어지게 하는 것이다. 상태가 안 바뀐 물건(예: 둥지 반짝임)은 그대로 이어진다.
  - 개정 3: **반복 첫 칸 = 멈춘 모습(`draw`)** 이다(같은 자리·같은 픽셀, 빌드가 한 장으로 합친다). 그래야 anim 끝 칸 → 멈춘 모습 → (첫 칸 길이 뒤) 움직임으로 이어진다. 쉬는 자세가 없는 반복(흐르는 물 등)이 필요해지면 그때 L1로 예외를 연다.
- **일시 연출(`anim`)**: 이벤트 `[대상, 이름]`이 오면 `anims["대상.이름"]`을 한 번 재생하고 멈춘 모습으로 돌아간다. 시트에 없으면 건너뛴다. 대상이 `@서는자리`(그 자리에 선 캐릭터)인 이벤트는 캐릭터 시트 몫이라 화면 시트는 보지 않는다.
- **`ms`는 정수 ms**다. 캐릭터 시트의 "50ms 배수" 규칙은 화면 시트에 두지 않는다(반짝임 120ms 같은 짧은 깜빡임이 필요하다). 렌더는 이미 rAF로 매 프레임 돌므로(`src/engine/loop.ts`) `loop` 추가 비용은 프레임 고르기 함수 하나다.
- **busy 길이**: 화면 시트에 있는 anim은 그 길이(ms 합을 60Hz 틱으로 올림)가 그 이벤트의 busy 길이가 된다. 없으면 지금처럼 `TIMING.anim`(30틱)이다. 그래서 Luna가 프레임 시간을 정하면 연출 박자가 그대로 따라간다.
- **anim 재생 중에는 그 물건(`ids` 포함)의 멈춘 모습·`loop`를 그리지 않는다.** anim 프레임이 그 자리를 대신한다. 끝나면 (그때의) 멈춘 모습으로 돌아간다.
- ADR-0065 "엔진은 `events`로만 반응한다"와의 관계: **반응(연출)은 이벤트로만** 한다. 멈춘 모습은 추측이 아니라 데이터(`when`)가 정한 것이고 히트 박스 `variants`와 같은 규칙이다. 이렇게 해야 게이지 0 리셋 뒤(A3, 까치가 바닥에 남음)와 M2 세이브 로드 뒤 화면이 맞는다. ADR 문장을 바꾸지 않고 해석을 기록하는 것이라 L1이다.

### 4-1. anim 갈래 (`variants`) — 개정 1
같은 이벤트가 물건 위치에 따라 다른 자리에서 나온다. 화면 1에서는 `magpie.ruffle`(둥지 위: `onEnter`·fallback / 바닥: `magpie_squeak_again`)과 `magpie.peck`(둥지 위: `hook_jjuk_pecked*` / 바닥: `magpie_stretch_pecked`)이다. anim 프레임의 `at`은 고정이라 한 장으로는 한쪽에서 까치가 순간이동한다.
- anim에 선택 필드 `variants: [{ when, ms, frames, layer? }]`를 둔다. 규칙은 hotspot `variants`·물건 `states`와 같은 **첫 일치, 없으면 기본**이다. 갈래의 `layer`가 없으면 `'back'`이다(state와 같다. 기본 anim의 `layer`를 물려받지 않는다).
- **평가 시점: anim 직전에 보이던 플래그**(4-2절의 "보이는 플래그", 보통 이 행동의 `step` 앞)로 고른다. `ruffle`·`peck`은 플래그를 안 바꿔서 앞뒤가 같다. 나중에 상태를 바꾸는 anim에 갈래가 붙으면 "지금 있는 자리에서 출발"이 맞기 때문이다.
- 퍼즐 데이터(화면 JSON 이벤트 이름)는 그림 위치 때문에 바꾸지 않는다. 이벤트를 `ruffle_ground`처럼 나누는 안(#157 제안 B)은 버렸다. 화면 2에서 자리가 바뀌는 물건이 나올 때마다 이름이 늘어난다.

### 4-2. 멈춘 모습이 바뀌는 시점 — 개정 1
지금 엔진은 `step` 결과를 이벤트 재생 **전에** 반영한다(`src/core/scene.ts` `runAction`). 멈춘 모습을 그 플래그로 바로 고르면 `magpie_squeak_down`에서 삑삑이가 닭을 누르는 동안 까치가 이미 바닥에 있다가 `fly_down`으로 둥지에서 다시 내려온다(순간이동 + 두 번 내려옴). 그래서 물건마다 **보이는 플래그**를 따로 두고, `step` 뒤에도 그 행동의 이전 플래그로 그리다가 아래 시점에 바꾼다.
- **(a)** 그 물건(`ids` 포함)의 anim이 `show`에 있으면 **그 anim이 시작될 때** 새 플래그로 바뀐다. anim이 끝나면 새 멈춘 모습이다.
  - 그래서 **상태를 바꾸는 anim은 첫 칸 = 출발 자리, 마지막 칸 = 도착 자리**로 그린다. `fly_down`은 둥지 → 바닥, `fly_up`은 바닥 → 둥지.
- **(b)** 그 물건 anim이 `show`에 없으면 **`show`의 첫 anim이 끝날 때** 바뀐다. `hook_jjuk_nest_key`에서 열쇠는 쭉이 `reach_hang_up`이 끝나는 순간 둥지에서 빠지고, 그다음 `key_got` 말풍선이다. 설계 U3 "매달려 뻗어 열쇠 집기"와 맞다. 그래서 `reach_hang_up` 마지막 칸은 **손이 열쇠를 쥔 모습**으로 그린다(캐릭터 시트 몫).
  - (b)는 휴리스틱이다. 지금 화면 1에서 상태를 바꾸는 규칙 3개(`squeak_down`·`stomp_back`·`nest_key`)는 맞는 것을 확인했다. 첫 anim이 그 행동의 연출이 아닌 규칙이 생기면 그때 `show` 안에 명시 표시(예: `{ "commit": true }`)를 넣는 L1로 올린다.
- 게이지 0 리셋(A3)·세이브 로드처럼 재생할 이벤트가 없으면 **바로** 새 플래그다(지금 규칙과 같다).
- 퍼즐 판정·히트 박스는 언제나 `step` 뒤 진짜 플래그를 쓴다. 보이는 플래그는 그림에만 쓴다. 연출 중에는 busy라 입력이 없으니 둘이 어긋난 채로 클릭되는 일은 없다.

### 5. 물건 하나, ID 여럿 (`ids`)
- `ids`가 있으면 그 물건이 여러 대상을 맡는다. 없으면 키가 곧 ID다. 시소는 `seesaw = { ids: ['seesaw_left', 'seesaw_right'] }`로 널빤지 한 장이다(설계 3절 "시소 두 끝은 한 물건").
- `ids`에 있는 대상으로 오는 anim(`seesaw_left.plank_bounce`, `seesaw_right.plank_bounce`)은 이 물건을 바꿔 그린다. 방향이 반대라 2개를 따로 그린다.
- 판정(히트 박스)은 지금처럼 spot별 상자다. 호버 외곽선은 널빤지 전체가 켜지고, 어느 끝인지는 커서 라벨이 알린다.
- Q1 답: 시소는 사람이 서 있어도 **수평 고정**이다(설계 1-3절). 기울기는 `plank_bounce` 안에서만 보인다.
  > 대체됨(Q1만, 2026-11-19): [시소 올라서기 + 무게 기울기](2026-11-19-seesaw-boarding-and-tilt.md). 사람이 선 끝이 내려간다(#397).

### 6. 앞뒤 순서 (설계 1-4절)
그리는 순서는 다음과 같다.
1. 배경 → `layer: 'back'`(기본) 물건을 `objects`에 적은 순서로
2. 캐릭터와 `overlay`(`sortY` 있는 조각)를 **발 y 순서**로 섞어서. 발 y가 `sortY` 이하인 캐릭터는 조각 뒤, 큰 캐릭터는 앞이다. 바구니 앞판(`sortY` 236 = 바구니 바닥)이 바구니 **안** 캐릭터만 가리고, 바구니 앞을 지나가는 캐릭터(발 y 244)는 가리지 않는다.
   - 이 규칙은 바구니 안 캐릭터의 발이 `sortY` 이하일 때만 맞는다. 지금 엔진은 손을 놓으면 "지금 x 바로 아래, 발 y = `floor.y`(244)"로 옮긴다(`src/core/scene.ts` `floorPoint`). 그러면 바구니 안 캐릭터도 앞판 앞에 그려져 앞판이 아무도 못 가린다(Luna 리뷰). 그래서 고리에서 바닥으로 가는 경우(설계 4절 1·2·3·13번)는 **바구니 안 착지 점 발 (160, 235)** 에 떨어진다. 13번은 날아간 사람의 x가 시소 쪽(220)이라 "바로 아래" 규칙으로는 바구니에 못 들어가므로 **고정 점**이어야 하고, 두 사람이 같은 점에 겹쳐도 된다(포개짐).
   - 앞판 그림은 외곽선을 포함해 **225~236**(테두리 3줄 + 엮은 앞벽)이고, 발 235면 **발 위 10px**를 가린다. 보이는 높이는 삑삑이 15px, 묵직이 20px, 쭉이 32px이다(1-4절 "허리 위만 보인다"). 나올 때는 그냥 걸어 나가고, 발 y가 236을 넘는 순간 앞판 앞으로 나온다.
   - 개정 1: 처음 기록은 "앞판 226~236, 보이는 높이 16/21/33"이었는데, PR #165 시트의 앞판은 외곽선과 테두리 때문에 223~236이라 발 위 12px를 가렸다(13/18/30, Theo 리뷰). 삑삑이 13px면 머리만 남아 "누가 바구니에 있나"가 1배에서 안 읽힌다. 그래서 숫자가 아니라 **그림을 고친다**(테두리를 2px 내려 앞벽 안으로). 규칙: **앞판 불투명 영역은 발 위 10px 이하.**
   - 이 값은 그림이 아니라 캐릭터 위치(히트 박스도 따라감)라 `art/scenes/*.mjs`가 아니라 화면 JSON에 둔다(예: `hook` 자리의 `releasePoint: [160, 235]`). `src/core/puzzle/` 타입이 바뀌는 코어 PR이라 10절 2단계에서 정한다. 그 전까지 앞판은 아무도 가리지 않는다(9절 폴백과 같다).
3. 고리에 매달린 캐릭터(항상 캐릭터 맨 앞)
4. `layer: 'front'` 물건 → 효과 레이어 → 말풍선(DOM)

- `layer`는 물건이 아니라 **state·`default`·anim 단위**다(Luna B). 둥지 위 까치는 뒤, 바닥의 까치(state)와 `fly_down`은 캐릭터 앞이다. 까치가 쭉이를 노려보는 장면에서 다리에 가리면 안 되기 때문이다.
- #157 제안의 `front: true` + `back()` 나눔은 이것으로 바꾼다. 바구니 앞판을 "모든 캐릭터 앞"에 두면 바구니 앞을 지나는 캐릭터의 다리가 가려진다.
- y 정렬은 `overlay` 조각에만 한다. 물건끼리는 적은 순서다.

### 7. 고리 손 기준점 (Q3)
- 고리(`hook`)는 물건이다. 매달린 캐릭터는 지금처럼 발 (160,160)에 세우고, 매달린 자세(`hold`) 프레임의 손 위치가 **(158,100)** 에 오게 그린다(설계 1-2절 "발 160,160 / 손 158,100").

## 11. 효과 자리 (`effect`) — 개정 4

**배경**: `park_fountain` 물줄기(켜짐 반복·아래부터 꺼짐·크게 솟았다 다시 뿜음)는 칸 그림이 아니라 엔진 입자 효과로 그린다(`park_fountain.md` 7절). 그런데 그리는 자리는 효과 레이어(캐릭터 위)가 아니라 **`back` 안, 재킷 바로 다음·분수대 테두리 앞면 앞**이다(1-4절). 지금 `back`은 "물건 그림 프레임 번호 목록"이라 그 사이에 입자를 끼울 방법이 없었다.

**선택지**
- A. **`objects`에 그림 없는 "효과 자리" 물건을 둔다** (Theo 제안). 적은 순서가 곧 그리는 자리라 6절 규칙이 그대로다. 단점: 엔진 효과 표에 효과 이름이 하나 늘 때마다 코드가 는다.
- B. 물줄기를 미리 그린 4칸 반복 그림으로 바꾼다(설계 12절 ① 대안). 단점: 아트 +4칸에 꺼짐·솟음 연출이 칸으로 또 필요하다(실제로는 +10칸 안팎). 입자보다 덜 살아 있다.
- C. 효과 레이어에 "뒤로" 표시를 붙인다. 단점: 효과 레이어는 물건 순서를 모른다. 재킷 앞·테두리 뒤라는 자리를 숫자(z)로 따로 적어야 해서 1-4절과 어긋날 수 있다.

**A로 한다.**

### 11-1. 모양
```js
// art/scenes/park_fountain.mjs (모양)
objects: {
  // ... 재킷까지 (뒤)
  jacket: { /* ... */ },
  water: {                                  // 효과 자리: 그림 없음
    effect: 'fountain_water',               // 엔진 효과 표(src/core/sceneFx.ts, 새 파일)의 이름
    area: [x, y, w, h],                     // 물줄기가 차지하는 화면 상자. 입자는 이 안에서만 그린다
    colors: [i1, i2, i3, i4],               // bosong-32 번호 4개: 물 밝음·물 중간·물보라 흰색·그림자 (Luna)
    mode: 'on',                             // default의 모드
    states: [{ when: { flags: { 'fountain.off': true } }, mode: 'off' }],
  },
  fountain: { /* 테두리 앞면 (앞) */ },
  // ... 창·자명종·손님
},
anims: {
  'fountain.water_off':   { effect: 'water', mode: 'stop',  ms: 900 },   // 아래부터 꺼짐
  'fountain.water_burst': { effect: 'water', mode: 'burst', ms: 1200 },  // 크게 솟았다 다시 뿜음
},
```
- 효과 자리는 `draw`·`loop`·`overlay`·`ids`를 갖지 않는다. 대신 `effect`·`area`·`colors`와 `mode`(default·state마다)를 갖는다. **`when` 첫 일치, 없으면 default**는 그대로다(4절).
- **좌표를 적는 유일한 예외**다(3절은 "그리는 쪽은 좌표를 적지 않는다"). 잘라 낼 그림이 없어서 빌드가 `at`을 만들 수 없기 때문이다.
- `layer`는 언제나 `'back'`이다. v1에서 `'front'` 효과 자리는 열지 않는다(필요하면 그때 L1).

### 11-2. 클릭·외곽선·폴백
- 효과 자리는 **대상 ID가 없다.** 히트 박스·호버 외곽선(10-1절)·`coveredIds`에 들어가지 않는다. 물줄기가 재킷 앞을 지나가도 재킷 클릭이 이긴다(설계 1-4절 마지막 줄과 같다).
- 엔진 효과 표에 없는 `effect`는 빌드 실패다. 배포본에서 메타만 앞서 나가는 일은 없다. 배경이 없을 때(9절 폴백)는 효과 자리도 그리지 않는다.

### 11-3. 연출 이벤트
- 화면 JSON 이벤트는 **진짜 대상 ID**로 보낸다: `{ "anim": ["fountain", "water_off"] }`. 퍼즐 검사기(`src/core/puzzle/validate.ts`)는 `anim` 대상이 핫스팟·서는 자리이기를 요구하므로 **코어 타입을 바꾸지 않는다.**
- 그림 메타에서 `effect`가 붙은 anim은 그 키의 대상 물건(`fountain` 테두리)이 아니라 **`effect`가 가리키는 효과 자리**를 바꿔 그린다. 테두리는 그대로 그린다. 빌드가 메타 `anims[...].object`를 효과 자리 키(`water`)로 적으므로, 엔진에서 "재생 중인 물건"(4절)·busy 길이(ms 합 → 틱, 8절 1500 상한)·4-2절 보이는 플래그가 다른 물건 anim과 같은 길로 간다.
- **보이는 플래그(4-2절)**: 효과 자리의 anim이 `show`에 있으면 그 anim이 **시작될 때** 새 플래그로 바뀐다(4-2 (a)). 그래서 `keeper_wake`는 `show`에 관리인 P1·P2 다음 `["fountain", "water_off"]`을 두면, 제어판 꾹 전까지 물이 계속 뿜다가 그때 아래부터 꺼지고 끝나면 `off`다. (b) 휴리스틱(첫 anim 끝)에 기대지 않는다.
- 게이지 0 리셋(A3)·세이브 로드처럼 재생할 이벤트가 없으면 바로 새 모드다(4-2절과 같다).
- **엔딩 ③ "솟았다 다시 뿜음"**: 끝난 뒤 모드도 `when`이 정한다(4절 "멈춘 모습은 상태에서"). 그래서 8번★ 규칙의 `do`에서 `fountain.off`를 다시 거짓으로 돌리고, 컷의 `show`에 `["fountain", "water_burst"]`를 둔다. 그러면 burst가 시작될 때 보이는 플래그가 바뀌고, 끝나면 `on`으로 계속 뿜는다. `do`에서 안 돌리면 burst 뒤에 물이 다시 꺼진 채로 ④가 이어진다(회색 배치 JSON에서 Luna 몫).

### 11-4. 엔진 효과 (`fountain_water`)
- 모드: 멈춘 모드 `on`(반복)·`off`(안 그림) + 연출 모드 `stop`(위쪽은 계속 떨어지고 아래부터 물기둥이 낮아짐)·`burst`(높이 1.5배로 솟았다가 `on` 높이로). 연출 모드 이름은 anim에만, 멈춘 모드 이름은 default·state에만 쓴다.
- **결정적(deterministic)**: 입자 위치는 `(화면 시계 ms, 입자 번호)` 해시로 고른다. `Math.random`을 쓰지 않는다. 같은 틱이면 같은 픽셀이라 재생 도구 스크린샷·그림 검사([playtest visual gate](2026-11-18-playtest-visual-gate.md))가 흔들리지 않는다.
- 픽셀은 `colors` 4색만 쓰고 1~2px 사각형(정수 좌표)이다. 반투명·블렌드 없음(ADR-0007 팔레트 규칙). 효과 자리 하나에 입자 **96개 이하**. `fillRect` 96번은 60fps 예산에서 무시할 만하다(#393 측정 기준 지금 프레임 비용은 CPU ×16에서도 여유).
- `loop`처럼 효과 자리의 시계는 그 자리의 anim이 끝나거나 모드가 바뀐 때부터 0으로 센다(개정 3 `loopStarts`와 같은 규칙). `stop` 끝 → `off`, `burst` 끝 → `on` 첫 박자로 이어진다.

### 11-5. 빌드 검사 추가 (8절에 더함)
- 효과 자리: `effect`는 엔진 효과 표에 있다. `area`는 정수 4개이고 480×270 안이다. `colors`는 0~31 서로 다른 4개이고 0번 ink·31번 hint가 아니다.
- 효과 자리의 `mode`는 그 효과의 멈춘 모드다. `effect` anim의 `mode`는 그 효과의 연출 모드다. anim의 `effect`는 효과 자리 키다.
- `effect` anim 키의 대상은 화면 JSON의 hotspot·spot ID다(물건 ID가 아니어도 된다. 8절 "어떤 물건의 ID"의 예외).
- 효과 자리는 `draw`·`loop`·`overlay`·`ids`·`layer`가 없다. 그림 물건은 `effect`·`area`·`colors`·`mode`가 없다.

### 11-6. 구현과 비용
- `SceneDraws.back`을 "프레임 번호 목록"에서 "프레임 또는 효과 자리" 목록으로 바꾸고(`src/core/sceneArt.ts`), 입자 계산은 순수 함수(`src/core/sceneFx.ts`) + 테스트, 그리기는 `src/engine/sceneArt.ts`. `src/core/puzzle/`·`src/core/save/`를 안 건드리는 **일반 PR**이다.

## 12. 멈춘 기울기 (`tilt`)와 판 밑 바닥 (`noFloor`) — 개정 5

**배경**: 진마씨 지적 "시소에 올라가는 게 어색해"(#397)로 시소가 탄 사람 무게에 따라 기운다(`magpie_nest.md` 1-5-4절). 기울기는 퍼즐 상태가 아니라 **판 위에 그려지고 있는 사람**으로 정해서 `when`(플래그)으로는 고를 수 없다. 처음 기록의 "수평 고정 널빤지"(반대 의견 Luna Q1)를 이 개정이 바꾼다.

**선택지**
- A. **기울기 값마다 멈춘 그림 칸**을 그리고 엔진은 고르기만 한다 (Luna 추천, Theo 채택).
- B. 엔진이 널빤지 칸을 열마다 세로로 밀어 그린다(Theo 처음 추천). 임의 px가 되지만 엔진에 새 그리기 코드가 들고, 판 무늬가 U6 칸과 같은 자리에서 끊기게 식을 맞춰야 한다.

**A로 한다.** 기울기 값이 5개(−6, −3, 0, 3, 6)로 닫혀 있고, 물건 원본의 `seesawTilt(d)`가 U6 `plank(d)`와 같은 함수라 그림 비용이 거의 0이다. B의 이점(임의 px)은 이 규격에서 안 쓴다.

### 12-1. 모양
```js
// art/scenes/magpie_nest.objects.mjs
seesaw: {
  ids: ['seesaw_left', 'seesaw_right'], draw: seesaw,
  tilt: {
    step: 3,                                   // d = step × (축 오른쪽 무게 합 − 왼쪽 무게 합)
    weight: { jjuk: 1, ppik: 1, mukjik: 2 },   // 그리기 상수(퍼즐 코어·규칙은 모른다). 없는 캐릭터는 1
    pivot: 247.5, run: 40,                     // 열 x가 내려간 px = round(d × (x − pivot) / run)
    draw: { '-6': …, '-3': …, 3: …, 6: … },    // 키 = d(0 제외). 0은 `draw` 그대로
  },
  noFloor: { box: [204, 200, 89, 38], y: 240 }, // 바닥 걷기 목표가 box 안이면 y를 240으로
},
```
메타에는 `tilt: { step, weight, pivot, run, frames: { "-6": 15, … } }`, `noFloor`는 그대로 적힌다.

### 12-2. 엔진 규칙 (`src/core/scene.ts`)
- **보이는 탑승(`riding`)**: 켜기 = 올라서기 착지 칸이 시작되는 틱, `board` 자리로 순간 배치(`place`·`release`)·기절 리셋·처음 배치, 탭 건너뛰기. 끄기 = 내려서기가 뜨는 틱, 그 사람의 캐릭터 anim이 시작될 때 퍼즐 `at`이 이미 `board` 자리가 아니면(발사 `launch_to_hook`, anim 이름은 보지 않는다), 다른 자리로 순간 배치. 판 위 끝 ↔ 끝 걷기는 계속 탄 채다.
- **어느 쪽 무게인가**: 자리 이름이 아니라 지금 발 x가 `pivot` 어느 쪽인가. 판 위를 걸어 축을 넘는 틱에 부호가 바뀐다.
- **그릴 칸**: 물건 anim이 재생 중이면 anim 칸(U6 튕김이 앞선다), 아니면 `frames[d]`, 그 칸이 없거나 d = 0이면 멈춘 모습 그대로. 층(`layer`)은 멈춘 모습의 층이다. 호버 외곽선은 지금 그리는 칸에 켜진다(10-1절 그대로).
- **판 위 발 높이**(그리기 전용): 탄 사람은 `(x, y + round(d × (x − pivot) / run))`에 그린다. 올라서기 공중은 **착지 전** d의 도착 열 높이로 0 → 그 값(1-5-2절 ③, #406), 내려서기 공중은 뜰 때 높이 → 0. 히트 박스·발 y 순서·말풍선 자리 계산은 걷기 좌표 그대로다(차이 6px 이하).
- **판 밑 바닥**: 바닥 걷기 목표(빈 바닥 누르기, `move floor`의 누른 점)가 어떤 물건의 `noFloor.box` 안이면 y를 `noFloor.y`로 옮긴다. 판 히트 박스 안 클릭은 원래 시소 대상이라 해당 없다. 판 뒤를 **지나가는** 경로의 깊이는 P2 그대로다.
- ~~U6 동안 판 위 발은 멈춘 기울기 값에 둔다.~~ → 개정 6(12-5절)에서 바꿨다. 칸별 기울기가 있는 물건 anim 동안은 그 칸의 d를 쓴다.

### 12-3. 빌드 검사 추가 (8절에 더함)
- `tilt.step`·`run`은 양의 정수, `pivot`은 수, `weight` 값은 양의 정수. `draw` 키는 0이 아닌 `step` 배수 정수이고 비어 있지 않다. 각 칸은 그 물건 히트 박스와 겹친다(멈춘 모습과 같은 검사).
- `tilt`를 단 물건의 `ids`에는 `board` 자리가 하나 이상 있다(올라탈 끝이 없는 기울기는 오타다).
- `noFloor.box`는 양의 크기 정수 4개, `noFloor.y`는 box 세로 범위 밖의 정수다.

### 12-4. 다시 볼 조건
- 기울기 값이 5개를 넘거나 무게가 늘어 칸이 6개를 넘으면 → B안(엔진 층 밀기)으로 바꾼다.
- 기울기가 퍼즐 단서가 되는 규칙이 생기면 → 무게가 코어로 들어가야 하므로 L2(ADR-0065).

### 12-5. anim 칸별 기울기 (`anims[...].tilt`) — 개정 6
**배경**: 멈춘 값에 발을 두면 정답 11번 절정에서 쭉이 발이 120ms 동안 판에 7px 묻힌다(설계 1-5-4절 2026-11-19 개정, PR #410). 엔진은 anim 칸 그림만 알고 그 칸의 널빤지 d를 모른다.

**모양**: 기울기(`tilt`)를 단 물건의 anim(과 그 갈래)에 칸 수와 같은 길이의 정수 배열을 둔다. 값 = 그 칸을 그린 `plank(d)`의 d.
```js
// art/scenes/magpie_nest.objects.mjs
'seesaw_right.plank_bounce': { ms: [60, 120, 80], frames: [plank(4), plank(7, …), plank(-2)], tilt: [4, 7, -2] },
```
메타에도 `"tilt": [4, 7, -2]` 그대로 적힌다.

**엔진 규칙**: 탄 사람(`riding`)의 발은 그 물건 anim이 재생 중이고 `tilt`가 있으면 **지금 칸**의 d로 12-2절 식을 쓴다. 칸 고르기는 그리는 쪽과 같은 시계(`current.t`)라 판과 발이 같은 틱에 바뀐다(보간 없음). `tilt`가 없는 물건 anim은 지금처럼 멈춘 값이다. 그림 고르기(`tiltOf`·`frames[d]`)는 그대로다. 퍼즐 코어·규칙·히트 박스는 모른다.

**빌드 검사(8절에 더함)**: `tilt`는 대상 물건에 `tilt`가 있을 때만, 그리고 `frames`와 같은 길이의 정수 배열이어야 한다. 엔진 파서도 같은 검사를 한다.

**왜 그림 자동 측정이 아니라 숫자를 적나**: 칸 그림에서 판 윗면을 재는 것도 되지만, 효과(`whoosh`) 픽셀이 섞이면 틀린다. 그림 원본이 이미 `plank(d)`로 그리니 같은 d를 한 줄 더 적는 게 가장 싸고 정확하다. 리스크: 그림의 d와 `tilt` 숫자가 어긋나도 빌드가 못 잡는다 → 원본에서 같은 상수(`side * BOUNCE` 등)로 둘 다 만들어 막는다.
