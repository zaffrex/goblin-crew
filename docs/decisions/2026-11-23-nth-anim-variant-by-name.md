# 결정: 두 번째부터 짧은 판은 그림 쪽 이름 `이름#k`로 붙이고, 화면 데이터는 안 바꾼다

- 레벨: L1
- 날짜: 2026-11-23
- 결정자: **[FE Theo]** (그림 데이터 쪽 리뷰 Luna, PR에서 합의)
- 참여: Theo, Luna(리뷰)
- 출처: #765 2/2, ADR-0761 H5 "두 번째부터는 짧은 판을 쓴다", M2 플래닝 회의록(2026-11-22) 공통 줄

## 배경
ADR-0761 H5가 "중간 성공의 엉뚱함은 두 번째부터 짧은 판"을 요구한다. 대사는 이미 `say: [화자, [첫 글, 두 번째 글]]`로 n번째 변형을 고른다(`pickText`, 규칙·폴백별 발동 횟수). anim에는 그런 길이 없었다.

## 선택지
- A. 화면 데이터 `anim: [대상, [긴 판, 짧은 판]]`(대사와 같은 꼴). 장점: 퍼즐 문서에서 바로 보인다. 단점: `src/core/puzzle/` 타입·검사·`step` 이벤트 형식을 바꾸는 코어 PR(리뷰 2명), 이벤트 이름이 배열이 되어 엔진 곳곳이 바뀐다.
- B. 그림 쪽(캐릭터 시트 `anims`, 물건 메타 `anims['대상.이름']`)에 `이름#k`를 두면 엔진이 k번째 발동부터 그걸 쓴다. 장점: 화면 데이터·코어 변경 0, 짧은 판이 없으면 지금과 같다(그림이 붙는 대로 생김). 단점: 퍼즐 문서만 봐서는 짧은 판이 있는지 모른다.

## 결정
**B.** 짧은 판은 그림 길이 문제라 그림 데이터에 두는 게 맞고, 코어를 안 건드린다.
- 횟수 `n`은 대사 변형과 같은 값(규칙 ID별, 폴백은 출처·대상·동사·캐릭터별)이다. 새 판(처음부터)이면 지워진다. 세이브 안 함.
- `2 ≤ k ≤ n` 중 가장 큰 `이름#k`, 없으면 원래 이름.
- 검사: 캐릭터 시트 변형은 원래 자세가 있고 **끝 칸이 같아야** 하며 공중 칸(`air`)이 없어야 한다(뛰어오르기는 처음 판만). 물건 메타 변형은 원래 anim과 `object`·`hold`가 같아야 한다.
- 새 칸 없이 만들 때는 시트 빌드의 `reuse`를 쓴다(예: 삑삑이 `common.shiver#2`).

## 반대 의견
가장 강한 반론: "퍼즐 작가(Kai)가 화면 JSON만 보고 정답 길 길이를 셀 수 없다." → 길이 숫자는 replay·`#67` 리포트가 그림 길이로 재므로 거기서 보인다. 문서에서 꼭 보여야 하면 A로 옮긴다.

## 다시 볼 조건
- 짧은 판을 화면마다 다르게 해야 할 때(같은 캐릭터 자세라도 화면 A만 짧게) → A 검토.
- "두 번째"를 새 판(처음부터)에도 이어 세야 한다는 QA·진마씨 피드백이 오면 → 페이지 단위로 세기(`seenClears`처럼).
