# 결정: 기본 배포 링크는 늘 팀이 개발 중인 최신 main이다 (진마씨 배려로 막지 않는다)

- 레벨: L3(진마씨 방침)
- 날짜: 2026-11-22
- 결정자: 진마씨
- 참여: 진마씨(방침), PM Noah(기록)
- 출처: `#goblin-meeting` M2 플래닝 스레드 (2026-11-22), 진마씨 "나를 배려할필요는 없고 그냥 zaffrex.github.io/goblin-crew 에 항상 너희들이 개발하고 잇는 최신을 올려줘. 난 신경쓰지말고" 관련: #766, #789, #767

## 배경
팀은 진마씨 재플레이가 진행 중일 때 배포본이 바뀌지 않게 "쿼리 없는 기본 링크는 그대로 둔다"는 지킬 선을 두었다([multi-screen-link-before-planning](2026-11-21-multi-screen-link-before-planning.md) 1번, #766 이슈 본문 "진마씨 플레이 중에는 첫 화면을 바꾸는 머지를 미룬다"). 그래서 화면 연결은 `?playtest=1&order=` 뒤에만 있었고, 진마씨가 "화면 1을 클리어하면 2로 넘어가는거 아니야?"라고 물으셨다. 진마씨는 팀이 자신을 배려해 기본 링크를 묶어 두지 말고, 늘 개발 중인 최신을 보고 싶다고 하셨다.

## 선택지
진마씨 방침이라 선택지는 없다. PM은 방침을 아래 규칙으로 옮겼다.

## 결정
1. **기본 링크 = 최신 main.** main 머지 = Pages 자동 배포(ADR-0005)는 그대로다. 진마씨가 플레이 중이라는 이유로 머지를 미루거나, 기본 링크 동작을 고정하지 않는다.
2. **새 기능은 머지되면 기본 링크에서 켠다.** "진마씨가 보는 화면이 바뀌니까"라는 이유로 `?playtest=1` 같은 쿼리 뒤에 숨기지 않는다. 쿼리는 팀 도구용(`?screen=` 화면 하나, `?playtest=1&order=` 순서 덮어쓰기, 재생·프레임 도구 훅)으로만 쓴다.
3. 기본 링크가 화면을 이어서 보여 주는 순서는 `content/screens/order.json`이다(#789). 지금은 임시 순서(`magpie_nest` → `park_fountain` → `laundromat`)이고 바꾸는 조건은 [default-link-interim-order](2026-11-22-default-link-interim-order.md) 그대로다.
4. 막는 것은 팀 품질 기준뿐이다: CI·리뷰 게이트를 통과한 것만 main에 들어간다. 깨진 판을 고의로 올리지 않는다.
5. 이 방침은 **기본 링크에 무엇이 올라가는가**에 대한 것이다. 팀이 먼저 진마씨께 **플레이를 부탁하는 글**의 조건([near-final-only-to-ceo](2026-11-21-near-final-only-to-ceo.md))과 진마씨가 직접 요청하면 링크를 드리는 규칙([ceo-midpoint-check](2026-11-22-ceo-midpoint-check.md))은 바뀌지 않는다.

이 기록으로 [multi-screen-link-before-planning](2026-11-21-multi-screen-link-before-planning.md)의 지킬 선 1·2("쿼리 없는 배포본은 지금과 똑같다", `order.json` 기본값은 화면 1만)는 대체된다. 같은 기록의 나머지(세이브 시작 조건 등)는 그대로다.

## 반대 의견
가장 강한 반론은 "진마씨가 플레이하는 도중에 배포가 바뀌면 새로고침 뒤 화면이나 순서가 달라져 헷갈릴 수 있다"는 것이다. 대응: 진마씨가 직접 "신경쓰지 말라"고 하셨다. 대신 배포본을 크게 바꾸는 머지(순서 변경, 세이브 추가처럼 처음 화면이 달라지는 것)는 `#goblin-dev`에 한 줄 남기고, 주간 리포트에 그 주 배포 변화를 적는다.

## 다시 볼 조건
- 대외 공개(L3)를 준비할 때: 공개용 안정판 링크와 개발용 최신 링크를 나눌지 다시 본다.
- 진마씨가 "고정된 판으로 보고 싶다"고 하시면 그 판만 따로 링크를 드린다.
