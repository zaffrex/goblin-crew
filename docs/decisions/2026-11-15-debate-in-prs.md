# 결정: L2 ADR PR에 반대 담당을 두고, 코어 로직 PR은 리뷰어 2명

- 레벨: L1
- 날짜: 2026-11-15
- 결정자: **[PM Noah]**
- 참여: PM Noah, FE Theo (PR #95 반대 관점 리뷰)
- 출처: `#goblin-ceo` 사장님 질문 (2026-11-15) "너희들, 토론 충분히 하면서 진행하고 있는거 맞지?", 이슈 #94

## 배경
사장님 질문에 답하려고 최근 머지된 PR 30개를 봤다. ADR은 토론이 실제로 일어났다(#87 리뷰 13건, 4왕복, 수정 요청으로 구멍 2개를 잡음). 빈 곳은 두 가지다.
1. 회의 cron을 없앤 뒤 L2는 대부분 PR에서 끝난다. 그래서 회의마다 하던 반대 담당자 지정이 쓰일 자리가 없어졌다.
2. 코어 규칙 엔진 #93(990줄)은 리뷰어가 1명(BFS 관점)이었다. 리뷰는 구체적이었지만, 퍼즐 설계 관점에서 규칙을 읽은 사람은 없었다.

## 선택지
- A. 그대로 둔다 (실행 비용 0 / 토론이 ADR에만 몰리고, 코어 코드는 한 관점으로만 검증됨)
- B. 정기 회의를 되살린다 (토론 자리가 생김 / 사장님 L3 결정 "조건으로 진행"과 충돌, 4명 실행 비용)
- C. PR 안에서 보강한다: ADR PR에 반대 담당 1명, 코어 로직 PR에 리뷰어 2명 (회의 없이 토론 자리를 만듦 / 코어 PR마다 리뷰 실행 1번 추가)

## 결정
C. 토론은 이미 PR에서 가장 잘 일어나고 있으니 거기를 보강한다. 운영 매뉴얼 토론 규칙 4, ADR 흐름 3, PR과 머지 9에 반영했다.
- 반대 담당은 억지 반대가 아니다. "이 결정이 틀렸다면 어디서 틀렸나"를 최소 1개 구체적으로 쓰고, 결론은 승인이어도 된다.
- 코어 로직 PR: `src/core/puzzle/`, `src/core/save/`, 그리고 이 경로 밖의 퍼즐 검사 진입점. #67 BFS는 `src/core/puzzle/bfs.ts`라 이미 경로 안이다. `src/core/game.ts`(엔진↔`step` 연결)는 M1 실입력 재생 판정이 검증하므로 1명으로 둔다.
- 게이트는 승인 1개로 초록이 되므로 자동 머지를 걸지 않는다. 에이전트가 실제로 읽는 머지 규칙은 실행 프롬프트라 `scripts/build-prompt.sh`에도 예외를 넣었다(Theo 리뷰 1번).
- 두 번째 ✅를 단 리뷰어가 바로 머지한다(작성자를 다시 부르는 실행 1번을 아낌, Theo 리뷰 3번).
- 재승인 범위: 반영 커밋 뒤에는 수정 요청한 리뷰어만 다시 승인한다. 반영 커밋이 다른 리뷰어가 본 부분을 바꾸면 그 사람도 부른다(Theo 리뷰 2번). 이걸 안 하면 4왕복 PR의 리뷰 실행이 4번에서 8번으로 는다.
- 리뷰 제목을 정해 회고에서 센다: 반대 담당 `### 반대 담당: 틀렸다면`, 두 번째 리뷰어 `### 관점 리뷰(<관점>)`(Theo 리뷰 6번).

## 반대 의견
- 비용: 코어 PR마다 리뷰 실행이 1번 늘어난다(사장님 구독 사용량). M1까지 코어 PR은 3~5개라 감당할 만하다고 봤다. #57 한도 규칙에 걸리면 먼저 줄인다.
- 강제력: 게이트가 승인 2개를 검사하지 않아 규칙으로만 지킨다. 실수로 자동 머지를 걸면 1명 승인으로 머지된다. 어기는 일이 생기면 `review-gate.sh` 경로별 승인 수 확장을 Sam과 검토한다(CODEOWNERS 대상, 사장님 Approve 필요).
- 쏠림(Theo): 두 번째 리뷰어가 퍼즐 설계 관점 Luna로 몰리는데, Luna는 임계 경로 #66을 쥐고 있다. PM이 리뷰어를 고를 때 한 사람에게 코어 리뷰를 한 번에 하나만 맡긴다.
- 속도: M1 목표가 11/18이다. 두 번째 리뷰어를 기다리는 동안 임계 경로가 늦어질 수 있다. 조건 진행 규칙대로 기다리지 않고 바로 부른다.

## 다시 볼 조건

- `### 관점 리뷰` 제목 아래 지적 중 2주 동안 커밋으로 반영된 것이 0건이면 1명으로 되돌린다.
