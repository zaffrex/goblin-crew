# 결정: 구독 사용량 한도 대응 규칙 (잠정, 2주 보정)

- 레벨: L1 (사장님이 실제 한도 수치를 알려 주면 확정)
- 날짜: 2026-11-15
- 결정자: **[인프라 Sam]** 제안, PM 승인 대기
- 참여: 사장님 지시(#goblin-ceo 11/15), 이슈 #57
- 출처: #goblin-ceo 2026-11-15 "진짜 비용은 내 Claude 구독 사용량", 이슈 #57, `scripts/usage-report.sh`

## 배경
돈 비용은 0원이지만 에이전트 실행은 사장님 Claude 구독 사용량을 쓴다. Actions에서는 실제 토큰을 알 수 없어 실행 횟수·분(`scripts/usage-report.sh`)을 대리 지표로 쓴다. 최근 24h는 114회 중 실패 0, 역할당 18~33회(pm 33회/89분, designer 30회/129분, frontend 30회/116분)였다.

## 선택지
- A. 규칙 없이 사장님이 한도에 닿은 뒤 알린다 (단순 / 갑자기 멈춘다)
- B. 단계별 규칙을 두고 임계마다 조치한다 (예측 가능 / 대리 지표가 틀리면 과하게 멈춤)

## 결정
B. 주간 구독 한도 대비 사용률(사장님이 보는 화면 기준) 단계:
| 사용률 | 조치 |
|---|---|
| ~70% | Sam이 `#goblin-dev`에 1회 경고. 새 정기 회의는 보류 |
| ~85% | tick 간격 2배. 멘션 응답·리뷰·머지만 유지. 모델 하향(L1, PM) |
| ~95% | 사장님 호출(L3: 한도 상향 또는 일시 정지). 이벤트 응답 외 정지 |
루프 감지: 같은 역할이 1시간에 6회 이상 실행되거나 실패가 연속 3회면 Sam이 알린다.
임계는 추측이다. 2주간 사장님 사용량 화면과 `usage-report.sh` 수치를 대조해 보정한다.

## 반대 의견
가장 강한 반론: 분 단위 대리 지표는 큐 대기 시간을 포함하고 토큰과 어긋난다. 그래서 임계 수치는 "사용률"(사장님 화면) 기준으로 두고, 스크립트는 역할별 편중과 루프 감지에만 쓴다.

## 다시 볼 조건
2주 후 보정 때, 또는 실제로 한도에 닿았을 때.
