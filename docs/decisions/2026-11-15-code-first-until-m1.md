## 배경
팀이 일을 시작한 지 약 1시간이 지났다. 그동안 ADR 1개를 머지했고 ADR PR 3개(#14, #15, #17)와 ADR 이슈 2개(#7, #18)가 열려 있지만 게임 코드는 없다. 사장님이 이 점을 짚었다. 되돌리기 비싼 결정을 먼저 정한 것은 맞지만, 이대로 가면 문서가 플레이 가능한 결과물보다 앞서 나간다.

## 선택지
- A. 기존 계획 유지: 11/15 13:00 ADR 3개 머지 뒤 코드 시작, 퍼즐 원칙·데이터 모델도 ADR 승인 뒤 구현 (결정 근거가 촘촘함 / 첫 화면이 늦어지고 검증 안 된 문서가 쌓임)
- B. ADR 절차 중단, 코드부터 (가장 빠름 / L2 절차를 어겨서 헌장 위반, 나중에 재작업 위험)
- C. 코드와 ADR을 병행하고 코드가 ADR을 기다리지 않게 함 (빠르고 절차도 지킴 / ADR이 코드를 뒤따라가면서 결정을 뒤집을 수 있음)

## 결정
C.
1. **스캐폴딩(Vite + TS + Canvas 빈 화면, 빌드, 테스트 러너)은 지금 바로 시작한다.** ADR-0004(#14)의 핵심(TS, Canvas 2D, Vite, 정적 `dist/`)에는 BE·인프라가 이미 승인했고, 남은 쟁점(말풍선 DOM/캔버스 등)은 스캐폴딩과 상관없다.
2. **M1까지 L2 결정은 ADR을 유지하되, ADR이 구현을 막지 않는다.** 퍼즐 설계 원칙(#18)과 퍼즐 데이터 모델은 동작하는 프로토타입 코드와 함께 또는 그 뒤에 쓴다. ADR은 "실제로 돌려 보니 이렇다"를 근거로 삼는다.
3. M0 ADR(#3, #4, #5, #7, #18) 외에 **새 ADR 주제는 M1 전까지 열지 않는다.** 필요한 결정은 해당 코드 PR 본문에 짧게 적고, L2에 해당하면 M1 뒤에 ADR로 정리한다.
4. 11/20(금) 목표를 "빈 배포 URL"에서 **"배포 URL에서 캐릭터 1명이 클릭으로 움직이는 화면"**으로 올린다.

## 반대 의견
- 가장 강한 반론: "데이터 모델을 ADR 없이 코드로 먼저 만들면 세이브 스키마(ADR-0006)와 어긋나서 다시 짜야 한다." → 데이터 모델 코드 PR은 Ben 리뷰를 필수로 하고, 세이브 직렬화 테스트를 붙인다. 프로토타입 단계 재작업 비용은 문서만 기다리는 비용보다 작다고 판단했다.
