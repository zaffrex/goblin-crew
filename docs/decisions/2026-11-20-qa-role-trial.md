## 결정
**B1.** 진마씨 결정. PM 추천안과 같다.

결정적 근거: 팀이 못 보는 주원인은 모델 계열보다 *정답을 알고 있음*이다. 이건 QA 실행에서 저장소 문서·퍼즐 데이터를 못 읽게 막으면 계열과 무관하게 풀린다. 계열 차이는 그다음 문제라 데이터로 판단한다.

시범 운영 방식:
- **하는 일**: 진마씨께 플레이를 요청하기 전과 화면을 새로 배포했을 때 배포 URL을 처음 하는 사람처럼 클릭해 보고, 막힌 곳·헷갈린 곳·어색한 곳을 GitHub 이슈로 남긴다. 진마씨 플레이 요청은 QA 통과 뒤에만 한다.
- **정답을 안 읽는다**: 약속이 아니라 실행 설정으로 막는다(저장소 체크아웃 없이 배포 URL과 브라우저 도구만). 설계·구현은 Sam(#456 하위 이슈).
- **모델**: Sonnet 5.5, effort medium. 정기 실행 없이 배포·플레이 요청 전에만 깨운다.
- **신원**: 새 Slack 앱 1개가 필요하다. 만드는 일은 진마씨 손이 간다(PM이 매니페스트 준비).
- **CODEOWNERS 대상**(`team/team.json`, `.github/workflows/agent.yml`) 변경은 진마씨 Approve가 필요하다.

## 반대 의견
PM 우려(선택지에 같이 올림): 같은 계열 모델이라 팀과 같은 맹점이 있을 수 있다. 진마씨도 이 점을 짚었다("다른 계열이 낫나"). 그래서 아래 1주 차 전환 기준을 결정에 넣었다. "재미"의 최종 판정은 계속 진마씨다. QA는 자잘한 버그 찾기에서 진마씨 시간을 빼는 용도다.
