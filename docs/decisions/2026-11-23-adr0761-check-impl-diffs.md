# 결정: ADR-0761 5절 반응 검사는 #822 구현대로 받고, 최단 길 비교만 후속으로 붙인다

- 결정자: PM Noah
- 참여: Ben(구현, PR #822), Theo(리뷰, PR #822)
- 출처: PR #822 본문 "리뷰 반영" 절, `#goblin-dev` 2026-11-23 Theo 글("PM 후속 줄로 받으면 돼요"), 이슈 #67

## 배경
ADR-0761 5절은 `정답 길 반응`·`오답 반응` 리포트를 정했다. #822 구현은 Theo 리뷰를 거치며 5절 글자와 세 군데가 달라졌다. ADR 본문을 고칠지, 구현을 되돌릴지, 차이를 받고 기록만 할지 정해야 했다.

## 선택지
- A. 세 차이를 모두 받고 기록만 한다 (빠름 / (2)의 가정이 틀려도 모른다)
- B. 세 차이를 받되 (2)만 후속 경고로 메운다 (작은 작업 1개 / 리포트 줄 1개 추가)
- C. 5절 글자대로 다시 구현한다 (ADR과 일치 / (1)은 Theo가 보인 대로 미끼를 놓쳐 더 나쁘다)

## 결정
**B.**
1. `오답 반응` = "정답 길 밖 상태의 반응"이 아니라 "도달한 모든 상태에서, `solution` 재생에 나온 `ruleId`가 아닌 행동의 반응". 분모는 도달 상태 전체(게이지 제외). 받는다. 상태 기준이면 정답 길 위 상태에서 누르는 미끼(H4)가 빠진다(Theo 재현: `laundromat` 0/0, 미끼 2개 누락).
2. `shortestPath` 재생 없음(세 화면 모두 `solution`이 최단이라고 가정, 미확인). 받되 **후속으로 확인한다**: `solution`의 행동 수가 BFS 최단보다 길면 리포트에 경고 한 줄(실패 아님). 그래야 "최단 길로 깨면 웃긴 박자를 건너뛴다"를 잡는다. 담당 Ben, #67 p2.
3. 코어 `src/core/puzzle/check.ts`가 아니라 `tests/content/`에 둔다. 받는다. 5절이 "숫자는 리포트만, CI를 실패시키지 않는다"라서 코어 검사 진입점일 필요가 없고, 코어 PR 2인 리뷰 비용도 아낀다.

ADR-0761 본문은 고치지 않는다(뒤집는 게 아니라 구현 세부라서). 이 기록이 5절 구현 메모다.

## 반대 의견
없었다. 가장 강한 반론: "(3)은 나중에 이 숫자로 CI를 막고 싶어지면 코어로 옮겨야 해서 두 번 일한다." 맞다. 그때는 ADR 5절 "숫자가 목표가 되면 반응을 억지로 늘린다"(Ben)부터 다시 본다.

## 다시 볼 조건
- (2) 후속 경고가 한 화면이라도 나오면 그 화면의 `정답 길 반응`을 최단 길 기준으로 다시 센다.
- 반응 숫자로 CI를 실패시키자는 제안이 나오면 (3)을 다시 본다.
