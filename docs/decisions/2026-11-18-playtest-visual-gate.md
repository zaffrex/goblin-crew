# 결정: 진마씨 플레이 요청 전에 "보이는 모양" 체크리스트를 통과시킨다

- 레벨: L1
- 날짜: 2026-11-18
- 결정자: **[PM Noah]**
- 참여: PM Noah (Theo·Luna 의견은 #330에서 받는다)
- 출처: `#goblin-ceo` M1 판정 2 재플레이 요청 스레드 (2026-11-18), 진마씨 "말풍선 좁지 않아? 이런 세세한 부분을 면밀하게 확인하고 체크해서 수정해". 이슈 #329, #330

## 배경
재플레이 요청 직후 진마씨가 말풍선이 좁다고 지적했다. 원인은 `#bubble`의 자동 폭이 `뷰포트 폭 − left`에 묶이는 CSS 문제였다(#329). 세 사람이 오른쪽에서 시작해서 첫 대사부터 보였다.
요청 전 점검(replay `--require-art`, frames, smoke)은 **동작**만 봤다. 폭·줄바꿈·잘림·겹침 같은 **보이는 모양**은 아무도 체계적으로 보지 않았다. PM이 확인한 스크린샷도 동사 버튼·게이지만 봤고 대사가 나오는 장면은 없었다.

## 선택지
- A. 지금처럼 동작 점검만 하고, 모양은 진마씨 피드백으로 고친다 (빠름 / 진마씨 시간을 세세한 버그 찾기에 쓰게 함. 11/15 방침 "일정보다 디테일 품질 우선"과 어긋남)
- B. 플레이 요청 전에 체크리스트 + 스크린샷 세트(3개 화면 크기 × 모든 대사 × 화자 위치, CJK 글꼴)를 통과시킨다 (요청이 몇 시간 늦어질 수 있음 / 이번 같은 문제를 팀이 먼저 잡음)
- C. B를 모든 PR 게이트로 건다 (가장 촘촘함 / 도구가 아직 없고 PR마다 비용이 큼)

## 결정
**B.** 진마씨께 플레이를 부탁하기 전에 PM이 #330 체크리스트(`docs/design/ui-detail-checklist.md`, Luna 작성 예정)를 통과한 스크린샷을 직접 확인한다. 확인한 커밋과 스크린샷 위치를 요청 글에 적는다.
결정적 근거: 진마씨가 맡기신 건 "재미있는지" 판정이다. 말풍선 폭 같은 건 팀이 먼저 잡았어야 했다.
UI를 건드리는 PR은 스크린샷 세트에서 해당 요소를 다시 찍어 붙이는 걸 권장한다. 의무(C)로 만드는 건 도구가 생긴 뒤에 다시 본다.

## 반대 의견
가장 강한 반론: "요청이 늦어져서 판정 2가 또 밀린다." → 11/15 진마씨 방침이 일정보다 디테일 품질이 먼저다. 스크린샷 도구가 생기면 한 번 돌리는 데 몇 분이라 지연은 처음 한 번만 크다.

## 다시 볼 조건
- 재생 도구에 "대사마다 한 장" 모드가 생기면: C(PR 게이트)로 올릴지 다시 본다
- 체크리스트를 통과했는데도 진마씨가 모양 문제를 다시 찾으면: 체크리스트 항목과 화면 크기 목록을 늘린다
