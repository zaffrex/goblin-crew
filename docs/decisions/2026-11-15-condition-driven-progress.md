# 결정: 시각·회의를 기다리지 않고 조건으로 진행한다, M1을 당긴다, status PR을 묶는다

- 레벨: L3(사장님)
- 날짜: 2026-11-15
- 결정자: 사장님
- 참여: PM Noah(운영 규칙과 M1 일정 정리), 인프라 Sam(지시 5번 담당)
- 출처: `#goblin-ceo` 사장님 지시 "진행 방식 점검했어" (2026-11-15). 관련: 사장님 PR #55(자동 머지), PR #61(머지 규칙 매뉴얼), 이슈 #57·#58(Sam)

## 배경
사장님이 진행 방식을 점검하고 운영 방식 변경을 L3로 지시했다. 원문 요지:
1. "정해 둔 시각이나 회의를 기다리지 마. 너희는 몇 분이면 끝내는데, 마감은 '11/16 12:00', '13:00 머지', '월 14:00 회의'처럼 사람 기준으로 잡혀 있어. 그래서 승인까지 난 ADR이 10시간 넘게 열려 있었어."
2. "마일스톤을 실제 속도에 맞춰 다시 잡아." 11/20 목표였던 "배포 URL에서 캐릭터가 클릭으로 움직이는 화면"은 11/15에 이미 됐다.
3. 자동 머지 PR #55가 머지되면 PR을 열 때 `--auto`를 건다. 매뉴얼의 머지 규칙도 맞춘다.
4. "status.md만 바꾸는 PR은 줄여. 정기 작업당 한 번으로 묶어."
5. (Sam) 실행 횟수·시간 기록과 구독 한도 규칙, Dependabot 정리, 봇 계정 공유 승인 검증 검토.

팀이 사람 회사의 달력(정기 회의, 마감 시각)을 그대로 가져와서, 몇 분이면 끝나는 일이 다음 회의 슬롯까지 기다렸다. 실제 예: ADR-0004(#14)·ADR-0005(#17)는 승인 2개가 모인 뒤에도 "12:00 2라운드 마감"을 기다렸다.

## 선택지
- A. 회의·마감 시각을 유지하되 간격만 줄인다 (익숙함 / 기다림이 줄 뿐 없어지지 않는다)
- B. 진행을 **조건**으로 바꾼다: "게이트가 초록이면 머지", "리뷰 2개가 모이면 확정", "앞 이슈에 승인 1개가 달리면 다음 이슈 시작". 시각은 사람(사장님)이 답해야 하는 곳과 주간 리포트에만 쓴다 (기다림이 없어짐 / 조건이 안 채워질 때 멈춘 걸 알아채는 장치가 필요)

## 결정
**B.** 사장님 지시이고 팀 운영 방식 변경이라 L3로 기록한다. 세부 규칙은 PM이 정했다(`docs/team/operating-manual.md` "진행은 조건으로", "회의", "메모리와 연속성" 절. 머지 규칙은 PR #61의 "PR과 머지" 절).

1. **조건으로 진행한다.**
   - 이슈·PR의 "마감"은 시각 대신 **완료 조건과 시작 조건**으로 쓴다. 예: "#65에 승인 1개 → #64 시작", "승인 2개 + PM → ADR 머지".
   - 게이트가 초록이면 그 실행에서 바로 머지한다(일반 PR은 `--auto`, ADR은 PM이 바로).
   - 승인이 모자라면 기다리지 않고 남은 리뷰어를 `[[역할]]`로 바로 부른다.
   - **멈춤 감지**: 부른 리뷰어가 두 번의 호출에도 답이 없거나, 조건이 반나절 넘게 안 채워지면 PM이 원인을 찾아 직접 풀거나 결정한다(교착 해소). 시각은 이렇게 "멈춘 걸 알아채는 기준"으로만 쓴다.
2. **회의는 조건으로 연다.** 정기 회의 슬롯을 없앤다. L2 안건이 생기면 PM이 바로 `#goblin-meeting` 스레드를 열고, 관련 역할의 1라운드와 반대 담당의 2라운드가 모이면 닫는다. 스탠드업은 `#goblin-dev` 보고로 대신한다. 플래닝은 마일스톤이 끝날 때 연다. 시각이 남는 것은 **금요일 주간 리포트(사장님 보고)와 회고**뿐이다.
   - 그래서 11/16(월) 10:00 플래닝과 14:00 설계 회의 #2는 열지 않는다. 안건은 각 PR·이슈에서 조건으로 처리한다(#15, #21, #42, 새 일정, 데이터 모델 #65).
3. **M1을 당긴다.** M1 수직 슬라이스(퍼즐 화면 1개를 배포 URL에서 처음부터 끝까지 플레이) 목표를 **11/18(수)** 로 잡는다. 엔진 재검토 기한(ADR-0004, 11/23)도 11/18로 당긴다. 판정은 임시 그림으로 한다(아트 품질 우선 방침은 그대로, 첫 실제 스프라이트는 병렬 트랙). 조건 순서는 `docs/team/status.md`에 있다.
4. **자동 머지**: PR을 열면 `gh pr merge --auto --squash`를 건다. 예외(ADR, 리뷰를 받고 싶은 문서 PR)는 PR #61 "PR과 머지" 절을 따른다.
5. **status.md PR을 묶는다.** status.md는 정기 실행 한 번에 한 번만 바꾸고, 그 실행의 다른 PR에 같이 넣는다. 이벤트 실행에서는 status만 바꾸는 PR을 열지 않고 다음 정기 실행에 몰아서 반영한다. 예외: 마일스톤·L3 결정이 바뀐 때는 그 결정 기록 PR에 같이 넣는다.
6. 5번 지시(실행 기록, Dependabot, 승인 신원 검증)는 Sam이 맡는다(#57, #58, #56).

## 반대 의견
- PM 우려 1: 조건만 있고 시각이 없으면, 조건이 안 채워진 채 멈춘 일을 아무도 알아채지 못한다. → 결정 1의 "멈춤 감지"(두 번 호출, 반나절)를 넣고, PM 정기 실행에서 열린 PR·이슈의 조건을 점검한다. Sam의 tick 감시(PR #55)도 실행 공백을 잡는다.
- PM 우려 2: 회의를 없애면 여러 역할이 같이 부딪히는 토론이 줄어든다. → L2 안건은 여전히 회의 스레드에서 1·2라운드와 반대 담당을 거친다. 바뀐 건 "언제 여느냐"뿐이다.
- PM 우려 3: 일정을 당기면 사장님의 "일정보다 디테일 품질 우선" 방침(2026-11-15, [사람 캐릭터 결정](2026-11-15-human-characters.md))과 부딪힐 수 있다. → M1 판정은 퍼즐 동작 기준이고 그림은 임시로 판정한다. 아트 디테일 일정(ADR-0007)은 당기지 않는다.
- 가장 강한 반론: 우리 속도는 "몇 분"이지만 리뷰 왕복과 깨어나는 지연이 쌓이면 실제로는 반나절 단위다. 11/18이 낙관적일 수 있다. → 밀리면 숨기지 않고 status에 새 날짜와 원인을 적는다.
