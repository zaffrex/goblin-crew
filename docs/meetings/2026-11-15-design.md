## 논의 요약

### 안건 1 — ADR-0003 (#15)
- **반대 담당 Ben 공격**: "화면 5개가 3인조로 버틴다는 근거가 예시 퍼즐 1개뿐이다. 너무 쉬운 화면을 잡아낼 검증 수단이 없다."
- **Luna 답**: 문서로 답함 → PR #21 (ADR-0018 퍼즐 설계 원칙 + `docs/design/mvp-screen-matrix.md`).
  - 화면 5개 × 능력 3개 매트릭스. 능력마다 4화면에서 필수, 세 능력이 모두 필수인 화면 2개.
  - 규칙: 한 능력이 정답 경로 능력 사용의 절반을 넘지 않는다, 어떤 능력도 2화면 연속으로 빠지지 않는다.
  - 검증: 능력 1개를 끄고 BFS를 돌려서 풀리면 그 능력은 필수가 아니다 → 퍼즐 데이터 모델에 요청.
  - 안정 ID: 세이브에 들어가는 ID(화면, 상태, 아이템, 서는 자리, 규칙)는 main 머지 뒤 이름을 바꾸지 않는다. 바꾸면 #10 마이그레이션 별칭을 같은 PR에 넣는다.
- PM 우려 "반응 애니메이션 최대 약 120개" → Luna: 고유 반응 120개 ≠ 고유 애니메이션 120개. 잠정 상한은 캐릭터당 공용 실패 리액션 4종, 화면당 고유 애니메이션 12개 이하, 1개당 4프레임 이하. Theo: 엔진의 범용 효과 레이어로 고유 프레임을 핵심 5~8개로 줄일 수 있다.
- **결론**: #15는 본문 수정 없이 승인. 매트릭스와 검증 방법은 #15가 넘긴 항목이라 ADR-0018(#21)에서 다룬다.

### 안건 2 — ADR-0004 (#14)
- **PM 질문**: 한글 대사를 Canvas `fillText`로 그릴지 DOM 말풍선으로 그릴지 정해야 M1 대사 작업을 시작할 수 있다.
- **Theo·Luna 답 (합의)**: 대사는 **DOM 오버레이**. 390px 폰에서 내부 11px 글리프는 약 9 CSS px이 되어 받침을 못 읽는다. DOM은 최소 14 CSS px을 지키고, 줄바꿈·글자 확대·스크린리더가 따라온다. 캔버스에는 글자를 그리지 않는다 (효과 글자·숫자는 스프라이트). → PR #14 결정 3 수정 (커밋 `5883b3b`).
- **대사 작성 규칙 고정**: 말풍선 한 줄 14자, 최대 2줄. 렌더 방식과 무관하며 콘텐츠 검증이 검사한다.
- **반대 담당 Ben 공격**: "자체 엔진은 M1 일정을 지킬 범위 정의가 없다. 대안과 비교한 숫자가 번들 크기뿐이다. 'N일 초과 시 Phaser 재검토' 같은 날짜 기준을 넣어라."
- **Theo 답**: 받아들임 (커밋 `27b2ce2`). 엔진 기본기 착수일부터 **달력 8일**(예상 3~4일의 2배) 안에 "퍼즐 화면 1개를 클릭으로 끝까지 푸는 빌드"가 main에 없으면 PixiJS와 Phaser를 둘 다 비교하는 새 ADR. 반박도 남김: "Phaser 위에 core를 따로 두면 씬·입력·트윈을 core 상태와 이중으로 맞춰야 해서 시간 절약을 갉아먹는다."
- **PM 판단 (일정 예산 시작일)**: 엔진 기본기 이슈가 따로 없고 #35(클릭 이동)가 사실상 첫 조각이다. **시작일 11/15, 기한 11/23(월)**로 status.md에서 추적한다.

### 안건 3 — ADR-0005 (#17)
- **Theo 반박**: Sam의 "아티팩트는 별도 오리진이라 localStorage가 섞이지 않는다"는 Pages 기준일 때만 맞다. 로컬 `npm run preview`는 PR이 달라도 모두 `localhost:4173`이다. → Sam 수용: 문장 수정, CI 아티팩트 빌드는 `VITE_SAVE_NS=dev`, 버전이 다른 세이브는 버리고 알림(ADR-0006 후속, Ben).
- **Luna 지적**: Pages URL은 첫 배포부터 공개·검색 노출된다. 가제는 상표 조사 전이라 IP 리스크다. → Sam 수용: L3 런칭 전까지 `<meta name="robots" content="noindex">`, 런칭 L3 때 제거. (프로젝트 사이트라 `robots.txt`는 효과 없음)
- **반대 담당 Ben 공격**: "11/20이 사장님 설정 1회에 걸려 있는데 대체 경로가 없다." → Sam 수용: 클릭 3단계 안내, 11/18까지 안 되면 아티팩트 프리뷰로 M0 판정(B 플랜).
- **PM 질문** "같은 계정 Pages의 localStorage 공유, `VITE_SAVE_NS`로 충분한가" → Ben: 다른 프로젝트와의 키 충돌은 `goblincrew.` 접두사로 충분하다. 다만 XSS는 오리진 단위라 접두사로 못 막는다. **세이브에 개인정보·비밀을 넣지 않는 것**이 방어선이다.
- **회의 뒤 상황 변화 (PM 기록)**: Pages 소스는 이미 GitHub Actions로 설정됐다. 11/20의 실제 의존성은 이제 deploy.yml PR #31에 대한 사장님 코드오너 Approve다(#24 결정). ADR 본문은 고치지 않고 이 회의록과 status.md에 적는다. B 플랜은 #31에도 그대로 적용한다.
