### 결정
1. **A를 퍼즐 설계 원칙으로 넣는다 (L2 → ADR-0018 개정, PM 초안, 리뷰 Luna·Ben).** 문장은 Luna 안:
   - 정답 최단 경로에 **웃긴 박자 3개 이상**, 그중 **1개 이상은 클리어 연출 밖**. 주 아하 단계는 담백해도 된다(아하는 깔끔하게 보이는 게 먼저).
   - **성공이 먼저 보이고, 엉뚱함은 그다음 박자**(C8 성공 리듬). 근거: #603에서 그림 없는 `…あれ？` 줄이 "왜 클리어?"로 읽혔다.
   - 정답 길 **중간** 성공에 붙는 엉뚱함은 늘어나는 시간 **1.5초 안**, 두 번째부터 짧은 판(Theo).
   - **클리어 컷은 1.5초 대신 탭 건너뛰기를 보장**한다(Luna 2라운드 반박 채택: U10은 4칸 + 까치 비행이라 1.5초에 안 들어간다). 처음 볼 때 길이는 카드 전까지 **4초 안**(Theo 2라운드 반박 채택: 건너뛰기가 있어도 처음 보는 사람은 끝까지 본다. 지금 `clearCut` 글 2초, U10 약 2~2.5초라 넉넉함). 숫자는 ADR 리뷰에서 Luna가 고칠 수 있다.
   - 검사는 "반응이 있다"까지만 본다. **웃김 판정은 Luna·Mia·진마씨 플레이**가 한다(Ben 우려 채택).
2. **B는 권장, 필수 아님.** 넣을 때 조건 두 개:
   - 상태를 바꾸지 않는 연출만(Ben). 검사로 경고한다(아래 4).
   - 공용 자세 + `say.text` 배열 변형을 먼저(0칸)(Theo).
   - `laundromat`: 이미 설계에 있는 `dryer_3`·`soap_vending` 장난감이 B 미끼다(Luna 정정, `laundromat.md` 153~154줄). JSON은 0칸으로 넣고, 제일 웃긴 `dryer_stretch`는 그림 단계에서 U5·U8(5칸)을 그대로 그린다.
   - `park_fountain`: 새 칸을 그리지 않는다(그림 이름 20개로 R1 12개를 이미 넘음, #422). 0칸 변형도 진마씨 스테이지 2 플레이 **뒤**에 본다(#601이 밀리지 않게).
3. **C는 데이터로 되는 것만** 한다: `onEnter` 개그, 물건 `loop`(0h). 캐릭터끼리 대기 장난(Theo 추정 4~6h)은 하지 않는다. 근거: 잘 푸는 사람은 기다리지 않아서 안건을 못 푼다(Theo·Luna). **다시 볼 조건**: 진마씨 M2 플레이에서 "멍하니 기다렸다"가 나오면.
4. **D는 하지 않는다.** "속았다" 짜증 위험, `laundromat`은 정답이 2단계라 첫 실패 보장이 곧 정답을 숨기는 일이 된다(Luna).
5. **반응 수 검사 (Ben)**: `explore()` 경로를 `step`으로 재생해 고유 `anim`/`say` 수를 센다. `solution` 재생과 `shortestPath` 둘 다, `common.*`는 따로 센다. 오답 반응 수와 "B 미끼가 상태를 바꾸는지" 경고도 낸다. 리포트 한 줄 + PR 본문에만 쓰고 **CI는 실패시키지 않는다**(Ben 우려 "숫자가 목표가 된다"). 하한선은 `magpie_nest`·`park_fountain` 실측을 본 뒤 Luna와 정한다.
   - `check.ts`가 `src/core/puzzle/` 안이라 **코어 PR**이다(리뷰 2명, 두 번째 ✅가 머지). 리뷰어 Theo + Luna 또는 PM.
   - "웃긴 박자 표시"를 화면 JSON에 넣지 않는다. 퍼즐 타입이 바뀌면 코어 PR이 되고 기계가 웃김을 못 센다. 웃긴 박자는 Luna가 화면 설계 문서 표에 적는다.

### 확인한 것 (Theo 2라운드 + PM 코드 대조)
Luna가 물은 "클리어 컷 건너뛰기가 지금 엔진에 있나": **반만 있다.** `src/core/scene.ts` `sceneTap`은 클리어 컷 **글**(`clear` 이벤트)을 0.4초(`clearSkipAfter`) 뒤 탭으로 넘긴다. 하지만 정답 규칙의 `anim`은 못 넘긴다(`walk`·`say`만 넘김). `clear`가 `show` 뒤에 붙으니 U10 급강하·셋 도망과 `park_fountain` 클리어 ①~④는 지금 건너뛸 수 없다.
→ Theo가 **클리어 규칙 연출 건너뛰기**를 한다: 대기열에 `clear`가 있는 동안 탭하면 남은 anim·fx·걷기를 끝 상태로 맞추고 `clear`로 넘어감. "두 번째부터"는 본 규칙을 UI 상태로 기억(`seenSay`와 같은 방식, 세이브 안 함). 2~3h + 테스트, `src/core/puzzle/` 밖이라 코어 PR 아님. **U10 PR보다 먼저** 올린다. 테스트는 "끝까지 본 판과 건너뛴 판의 마지막 프레임 상태가 같다"를 두 화면 정답 경로에서 비교(Theo 우려: 끝 상태 어긋남, #452와 같은 종류).
