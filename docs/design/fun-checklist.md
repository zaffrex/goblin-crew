# 퍼즐 화면 재미 체크리스트 (초안)

- 작성: **[디자이너 Luna]**, 2026-11-15
- 상태: 초안. 화면 설계 리뷰 때 쓰는 **점검표**다. 규칙(L2)이 아니다. M1 플레이테스트 뒤 효과가 있는 항목만 ADR-0018 후속 ADR로 올린다.
- 계기: 사장님 질문(#goblin-dev, 2026-11-15) "퍼즐을 정말 재미있고 원작에 가까운 수준으로 원한다. 재미 없을까봐 걱정이다."
- 관련: ADR-0003(세계관·캐릭터·예시 퍼즐), ADR-0018(PR #21, 퍼즐 설계 원칙), #66(화면 1 상세 설계), #72

## 왜 이 문서가 필요한가

ADR-0018은 화면이 **풀 수 있고 공정한지**를 검사한다(필수 능력 수, 막다른 상태 없음, 픽셀 헌팅 금지). 이 검사를 모두 통과해도 **지루한 화면**은 나올 수 있다. 예: 핫스팟 3개, 클릭 4번, 반응은 "안 돼요"뿐인 화면. BFS는 이런 화면을 잡지 못한다.

목표는 "원작에 가까운 **재미의 수준**"이다. 퍼즐 내용은 전부 우리 것이다.

### 출처와 IP 가드레일
- 이 문서는 협동 포인트앤클릭 **장르 전반**에서 흔히 말하는 재미 요소를 **패턴**으로만 정리했다. 특정 작품의 퍼즐, 레벨 구성, 대사, 연출을 분석하거나 옮기지 않았다.
- 원작을 실행하거나 파일을 열지 않았다(CLAUDE.md IP 가드레일: 다운로드·추출 금지).
- 이 문서의 예시는 모두 우리 세계관(뽀송빨래방)의 것이다.

## 재미 패턴 9개

| # | 패턴 | 한 줄 설명 | 우리 게임에서 하는 방법 |
|---|---|---|---|
| P1 | **장난감 상자** | 화면은 정답 경로가 아니라 **만지면 반응하는 장난감 상자**다. 정답과 상관없는 클릭도 웃음으로 보상받는다 | 눈에 띄는 물건은 셋 모두에게 반응이 있다. 정답과 무관한 "장난감 핫스팟"을 화면마다 둔다 |
| P2 | **같은 물건, 세 가지 해석** | 같은 물건에 세 사람이 전혀 다른 반응을 보인다. 그래서 "얘한테도 시켜 볼까?"가 자연스러운 다음 행동이 된다 | 핵심 핫스팟은 캐릭터×대상 칸이 전부 다른 반응이다(공용 리액션 재사용은 괜찮지만, 대사나 효과로 칸마다 다르게) |
| P3 | **엉뚱한 인과(아하)** | 정답 중 하나는 물건을 **원래 용도와 다르게** 쓴다. 풀고 나면 "그게 되네?" 하고, 돌아보면 납득이 된다 | 화면마다 "원래 용도가 아닌 사용" 1개 이상. 단, 실패 반응이 미리 힌트를 준다(ADR-0018 F2) |
| P4 | **협동 연쇄** | 한 사람의 행동이 다른 사람의 다음 행동을 **열어 준다**. 혼자서는 못 하는 걸 셋이 해낸다 | 정답 경로에 "A가 B를 위해 하는 단계"가 1개 이상(예: 묵직이가 쭉이를 발사) |
| P5 | **실패가 볼거리** | 실패를 일부러 다시 보고 싶을 만큼 웃기다. 실패의 손해는 작고 빠르다 | 다치는 실패는 크게 과장하고, 원래 상태로 빨리 돌아온다. 같은 실패를 두 번 하면 두 번째는 대사가 바뀐다 |
| P6 | **관찰 단서** | 화면을 보고 있으면 답이 보인다. NPC의 대기 동작이 성격과 약점을 보여 준다 | NPC 대기 애니메이션에 단서를 넣는다(예: 까치가 반짝이는 것만 보면 고개를 홱 돌린다). 상태는 바꾸지 않는다(ADR-0018 S1) |
| P7 | **작은 성공의 리듬** | 정답 경로 중간에도 "뭔가 바뀌었다"는 성공이 자주 온다. 마지막 한 번에만 보상이 몰리지 않는다 | 정답 단계마다 화면이 눈에 띄게 바뀐다(ADR-0018 R4: 정답 반응은 고유 애니메이션) |
| P8 | **반전으로 끝내기** | 클리어 순간에 마지막 개그가 한 번 더 터진다 | 클리어 컷에 "해냈다 → 그런데…" 한 박자를 둔다 |
| P9 | **캐릭터가 보인다** | 반응만 봐도 누가 했는지 안다. 성격이 반응을 만든다 | 쭉이(신중, 허세), 묵직이(힘, 단순), 삑삑이(겁, 꼼꼼)의 성격이 대사와 포즈에 드러난다(ADR-0003) |

## 체크리스트 (화면 설계 리뷰용)

숫자는 **시작값**이다. 아트 예산(ADR-0018 R1: 고유 애니메이션 4~12개)을 넘지 않는 범위에서 정했다. 장난감 핫스팟 반응은 대부분 공용 리액션 + 효과 레이어 + 대사 조합(R2)으로 만든다.

| # | 항목 | 기준 | 관련 패턴 |
|---|---|---|---|
| C1 | 장난감 핫스팟 | 정답과 무관한 핫스팟이 **2개 이상** | P1 |
| C2 | 반응 밀도 | 핵심 핫스팟(정답 경로에 쓰이는 것)의 캐릭터×대상 칸이 **전부 서로 다른 반응**이다. "아무 일도 없다"는 화면당 **2칸 이하**이고, 그 2칸도 대사는 있다 | P1, P2 |
| C3 | 아하 순간 | 정답 경로에 "원래 용도가 아닌 사용"이 **1개 이상** | P3 |
| C4 | 협동 단계 | 정답 경로에 "한 사람이 다른 사람을 위해 하는 단계"가 **1개 이상** | P4 |
| C5 | 실패의 단서 | 정답에 가까운 오답(순서만 틀림, 한 명만 틀림)은 **왜 안 되는지 보이는** 고유 반응이다 | P3, P5 |
| C6 | 실패 반복 변형 | 같은 실패 두 번째에는 다른 대사가 나온다(대사 1줄 추가. 애니메이션은 같아도 된다) | P5 |
| C7 | 관찰 단서 | NPC나 장치가 있으면 대기 동작에 해법 단서가 **1개** 들어 있다 | P6 |
| C8 | 성공 리듬 | 정답 단계마다 화면 상태가 눈에 띄게 바뀐다. "누르고 아무 일도 안 보이는" 정답 단계가 없다 | P7 |
| C9 | 마무리 개그 | 클리어 컷에 반전 한 박자가 있다 | P8 |
| C10 | 말로 하는 플레이 | 설계 문서에 "처음 하는 플레이어" 시나리오(행동 → 반응 순서표)가 있고, **30초 넘게 새 반응이 안 나오는 구간**이 없다 | 전체 |

C10은 구현 전에 재미를 점검하는 방법이다. 처음 하는 플레이어가 할 법한 행동 순서를 표로 쓰고, 각 행동에서 무엇이 보이는지 적는다. 지루한 구간이 문서에서 먼저 보인다.

### 보강안 (#66 상세 설계에 넣는다)

아트 비용을 늘리지 않는 것부터 적었다. 고유 애니메이션은 아래를 다 넣어도 R1 상한(12개) 안이다. 정확한 개수는 #66 문서에서 센다.

1. **장난감 핫스팟 2개 추가 (C1, 5번 구간)**. 정답 경로와 상태에 영향이 없다(BFS 상태 수도 그대로).
   - **빨랫줄의 남의 빨래**(아저씨 왕꽃무늬 내복): 쭉이 → 장대로 툭 건드리면 펄럭이며 얼굴에 덮인다(공용 "젖음" 리액션 + 대사 "…이거 누구 거야"). 묵직이 → 쿵 하면 빨랫줄 전체가 출렁, 빨래집게가 머리에 우수수(효과 레이어). 삑삑이 → "손님 빨래는 / 건드리면 안 돼요" (꼼꼼한 성격).
   - **빨래 바구니**: 쭉이 → 들여다보다 "푹신하네." (나중에 착지할 곳이라는 복선). 묵직이 → 쿵 하면 바구니가 튀어 오르며 양말이 흩날림. 삑삑이 → 안에 들어가 숨는다(겁 많은 성격, 고유 애니메이션 후보. 예산이 모자라면 대사로 대체).
2. **소리 단서 추가 (C7, 8번 구간)**. 까치 대기 동작에 "다른 새 울음 효과음이 나면 고개를 홱 돌리고 깃털을 부풀린다"는 반복 동작을 넣는다. 화면 진입 때 멀리서 새 소리가 한 번 나며 까치가 깃털을 부풀린다(상태 변화 없음, S1 준수). 그리고 묵직이 쿵 → 까치가 날았다 돌아오는 반응에 삑삑이가 "소리에 엄청 / 예민한가 봐" 대사를 붙인다.
3. **실패 반복 변형 (C6)**. 다치는 실패 3종(쪼임, 이마 맞음, 집게로 까치 집기)에 두 번째 대사를 1줄씩 넣는다. 예: 묵직이가 시소에 두 번째로 이마를 맞으면 "…알면서도 / 또 했어".
4. **마무리 개그 (C9)**. 쭉이가 열쇠를 들고 바구니에 착지해 셋이 환호한다 → 까치가 이번엔 **쭉이 장대의 반짝이는 집게**를 노리고 내려온다 → 셋이 다음 화면 쪽으로 허둥지둥 달려 나간다. 클리어 컷 1개에 까치 비행 프레임을 재사용한다.
5. **경로 길이는 그대로 4행동**. M1 화면이고 튜토리얼 성격이 있어 짧은 게 맞다. 다만 이 화면만으로 "재미의 상한"을 판단하지 않는다. M2 화면은 ADR-0018 M6 상한(10행동) 쪽으로, 중간 목표가 있는 2단 구조를 검토한다.

## 리스크와 한계
- **재미는 문서로 증명되지 않는다.** 이 체크리스트는 "지루할 가능성이 높은 화면"을 걸러 낼 뿐이다. 진짜 검증은 M1 빌드를 사람이 직접 해 보는 것이다(사장님, PM, Luna).
- 장난감 핫스팟은 아트·대사 비용이다. 화면당 2개를 넘기면 R1 예산과 부딪힌다. 대부분 공용 리액션 + 대사로 만들고, 고유 애니메이션은 화면당 1개까지만 쓴다.
- 장난감 핫스팟이 많으면 플레이어가 "이게 정답에 쓰이나?" 헤맬 수 있다. 장난감 반응은 **끝이 분명한 개그**(한 번 보고 끝)로 만들고, 상태를 남기지 않는다.
- 숫자(C1 2개, C2 2칸, C10 30초)는 감으로 정한 시작값이다. M1 플레이테스트에서 바꾼다.
