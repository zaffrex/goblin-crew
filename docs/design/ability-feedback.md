# 특기 쓰임 피드백 규격 (#284)

- 상태: 규격 v1 (2026-11-18, 디자이너 Luna). 연결은 FE Theo, 글자 그림은 Luna
- 근거: 판정 2 사장님 2차 플레이(이슈 #257, `#goblin-ceo` 2026-11-17 밤) "특기가 한 번도 발동 안 됨", PM 재현(#284 본문), ADR-0003(직선, 슬랩스틱), ADR-0018(단서 원칙), 시트 파이프라인 기록 5-1·5-2절
- 결정 기록: [2026-11-18-ability-feedback](../decisions/2026-11-18-ability-feedback.md) (L1)

## 0. 풀어야 하는 문제

코드에서 특기는 발동한다(대사가 나오고 게이지가 깎인다). 그런데 사람 눈에는 "걸어가서 서기만 함"으로 보인다. 원인은 셋이다.

1. **fx가 전부 같은 임시 그림이다.** `squeak_text`, `ting_text`, `dust`, `shake` 등 화면 데이터의 fx 14종이 모두 `drawSpark`(7px 노란 십자, `src/engine/placeholder.ts`) 하나로 그려진다. 소리 글자는 #68 이후 한 번도 그려진 적이 없다(`ja-text.md` 5절).
2. **"썼다" 신호가 늦다.** fx는 캐릭터 연출이 끝난 뒤에 뜬다. 삑삑이만 칸 신호 `cue`가 있다. 쿵은 흔들림도 글자도 없다.
3. **대사가 묻힌다.** 말풍선은 연출이 끝난 뒤에 뜨고, 0.4초 뒤부터 탭으로 넘어간다. 사장님처럼 결과를 보려고 다시 누르면 첫 대사를 못 읽는다.

のばす 장대가 대상 쪽으로 안 늘어나던 문제는 PR #288에서 풀었다(늘어나다 모자라서 멈춤).

## 1. 원칙

- **F-a 시그니처.** 특기를 실제로 쓰면 그 특기의 **시그니처**(캐릭터 연출 + 소리 글자)가 대상과 결과에 상관없이 늘 같은 모양으로 나온다. 플레이어는 결과보다 먼저 "발동했다"를 읽는다.
- **F-b 바로, 충분히.** 캐릭터 연출은 실행 첫 틱에 시작한다(지금도 그렇다). 소리 글자는 그 연출의 "박자" 칸에 뜬다. 실행 탭부터 0.4초 안이다. 소리 글자는 0.6초 이상 보인다.
- **F-c 결과는 그다음.** 성공이나 실패는 시그니처 뒤에 대상 쪽 반응(fx, 대상 연출)과 대사로 보인다.
- **F-d 거절은 시그니처가 없다.** 특기를 쓰지 않고 거절하거나 가로막히는 반응(삑삑이가 고리를 무서워함, 까치가 먼저 쪼음)은 시그니처를 내지 않는다. 대신 그 반응 연출이 첫 틱에 시작해야 한다. "아무 일도 없음"으로 보이는 쇼는 없어야 한다.
- **F-e 캐릭터 색.** 시그니처 글자는 그 캐릭터의 대표색으로 칠한다. 누가 했는지가 글자 색으로도 보인다.

## 2. 시그니처 3개

|---|---|---|---|---|

- 쿵만 0번 칸이 아니다. 0~1번 칸(무릎 들기, 내려찍기)은 "쿵을 준비한다"로 이미 읽히고, 글자와 흔들림은 발이 닿는 칸에 와야 무게가 산다. 실행 탭부터 400ms라 F-b 안이다.
- `stretch_text`·`stomp_text`는 새 fx다. `squeak_text`는 있는 fx에 모양만 붙인다.
- 위치: 글자는 지금 fx와 같은 기준점(`main.ts` `anchorOf`: 행동한 캐릭터 그림 위 끝 가운데)에서 4px 위에 가운데 맞춤으로 뜨고, 6틱마다 1px씩 위로 뜬다(지금 `drawSpark`와 같은 움직임). 말풍선은 연출이 끝난 뒤에 뜨므로 겹치지 않는다(아래 4절 길이 확인).

- 길이: 시그니처 글자는 **36틱(0.6초)**. 다른 fx는 지금 `TIMING.fx` 30틱 그대로다.

### 2-1. ドスン 묶음 (`stomp_text` 한 fx가 셋을 같이 그린다)

`cue` 하나에 fx 하나라서(5-2절), 셋을 fx 하나로 묶는다.
1. **글자** `ドスン`: 위와 같다.
2. **화면 흔들림**: 장면 층(배경·물건·캐릭터·fx)만 **세로로** 흔든다. HUD와 DOM 글자(말풍선·이름표)는 흔들지 않는다. 버튼이 움직이면 누르기 어렵다. 3틱마다 y 오프셋 `+2, −2, +1, −1, 0`(합 15틱 = 0.25초). 쿵은 위아래 힘이라 가로로는 흔들지 않는다.
3. **발밑 먼지**: 묵직이 발 양옆에 먼지 덩이 2개(4×3px, `lint` 칠, `dusk` 그늘)가 바깥으로 6px 밀려 나가며 12틱 뒤 사라진다. 기준점은 묵직이 그림 아래 끝 가운데다.

- 시트 그림의 2·3번 칸에도 먼지·충격선이 있다(`art/sprites/mukjik.mjs` common.stomp). 그것과 겹쳐도 괜찮다. 시트 먼지는 몸에 붙은 작은 것이고, fx 먼지는 바닥으로 퍼지는 것이다.
- 흔들림 리스크: 멀미. 2px·0.25초로 작게 두고, 쿵에만 쓴다(다른 fx는 흔들지 않는다). 재플레이에서 거슬린다는 말이 나오면 1px로 줄인다.

### 3-1. ぼふっ 묶음 (`poof_text` 한 fx가 글자 + 흙먼지를 같이 그린다, #526)

흙길 쿵(`park_fountain` 3절 7번, 단서 ②)의 **결과**다. 시그니처 `ドスン`(2-1)은 F-a대로 400ms에 그대로 뜨고, `ぼふっ`은 쿵 연출이 끝난 뒤(1100ms) 뜬다. "ドスン! … ぼふっ"는 한 박자 늦은 김빠짐이라 그대로 둔다.
- **이유**: #468 블라인드 판정에서 `ぼふっ`이 묵직이 머리 위, 곧 분수대 테두리 윗면 높이에 떠서 "분수가 낸 소리"로 읽혔다. 흙먼지는 아예 없었다. 2-1 발밑 먼지(회색 2덩이)는 어느 바닥에서나 같아서 흙이라는 표시가 못 된다.
- **글자 자리**: 쿵 자리(x 224, 발 y 244)의 오른쪽 발치, 흙 위. 시작 칸 x 252~281, y 234~244(발 아래 끝과 같은 높이)에서 5px 뜬다. `FX_TEXT_SPOT`의 `poof_text@mukjik`(`src/core/fx.ts`).
- **흙먼지**: 발 기준점(대상 상자 아래 끝 가운데)에서 양옆으로. 발 밑 ±12px는 비우고, 땅을 따라 최대 42px까지 낮게(최고 9px) 번진다. 먼지 덩이는 2px 흙 그늘(11 `8e5c3b`) 위 + 2px 흙덩이(10 `5a3a2e`) 아래, 절반에 1px 밝은 흙(13) 윗점. 흙덩이 8개는 작은 포물선. 0.5초(30틱) 안에 하나씩 꺼진다.
  - 밝은 흙(13)만으로 그린 첫 시안은 1배에서 묻혔다. 흙길 바탕 12 `c48a52`에 13 점이 12% 섞여 있다(캡처 픽셀을 셌다). 그래서 어두운 흙을 몸으로 쓴다. 회색 쿵 먼지와 색으로도 갈린다.
- 코드: `TEXT_PARTICLE_FX`(`src/core/fxShape.ts`). 물 입자 fx와 달리 글자도 그린다(`drawnByShape`에 안 넣는다). 입자를 먼저 그리고 글자를 그 위에 그린다.
- **하지 않은 것**: 남는 발자국. 그림만을 위해 퍼즐 플래그를 세워야 하고(BFS 상태가 는다), 묵직이 발에 가려진다. 이 묶음을 넣은 뒤 블라인드 재판정에서 "흙/무름"이 안 읽히면 그때 "장식 물건" 형식 개정(Theo 제안, #526)과 함께 다시 본다.

## 4. 칸 신호 여러 개 (`cue` 배열, 파이프라인 5-2절 개정)

고리 뻗기(규칙 9)는 한 연출 안에 신호가 둘 필요하다. 시그니처 `ビヨーン`은 0번 칸에, `キン`은 장대가 멈추는 1번 칸에 와야 한다. 지금 `cue`는 숫자 하나 = 바로 뒤 fx 하나다.

- **개정**: `cue`는 숫자 또는 **오름차순 숫자 배열**이다. k번째 신호는 그 연출 바로 뒤에 **이어진 fx 중 k번째**를 띄운다. 이어진 fx가 신호보다 적으면 남는 신호는 아무것도 띄우지 않는다. 숫자 하나는 `[n]`과 같다(지금 데이터 그대로 통과).
- 이어진 fx 뒤에 남은 fx(신호를 못 받은 것)는 지금처럼 연출이 끝난 뒤 차례로 뜬다.
- 시트 값(Luna가 시트 원본에 넣는다):

| 시트 | 연출 | `cue` | 비고 |
|---|---|---|---|
| 쭉이 | `common.reach_wobble` | `[0, 1]` | 0번 칸 `ms` 250 → **300**(= `claw.growMs`, PR #288 리뷰). 그래서 `キン`이 장대가 멈추는 순간에 뜬다 |
| 쭉이 | `reach_hang_up` | `[0]` | |
| 쭉이 | `common.stretch` | `[0]` | |
| 묵직이 | `common.stomp` | `[2]` | 쿵 칸 |
| 삑삑이 | `common.squeeze_chicken` | `1` | 그대로 |

- 길이 확인(말풍선과 안 겹침): 시그니처 36틱이 끝나는 시각은 쭉이 0.6초(연출 1.15초), 묵직이 0.4+0.6 = 1.0초(연출 1.1초), 삑삑이 0.2+0.6 = 0.8초(연출 1.0초)다. 셋 다 연출이 끝나기 전에 끝난다.

## 5. 화면 1 데이터 변경 (FE 연결 PR에서)

시그니처 fx를 특기 연출 **바로 뒤**에 넣는다. `→`는 show 순서다.

| 규칙 / 반응 | 지금 | 바꾼 뒤 |
|---|---|---|
| 8 `nest_stretch_short` | wobble → say | wobble → **fx stretch_text(jjuk)** → say |
| 9 `hook_stretch_short` | wobble → fx ting_text(hook) → say | wobble → **fx stretch_text(jjuk)** → fx ting_text(hook) → say |
| 정답 `hook_jjuk_nest_key` | reach_hang_up → say | reach_hang_up → **fx stretch_text(jjuk)** → say |
| 쭉이 `stretch` 반응 4개(magpie, seesaw_left/right, basket) | stretch → (대상 반응) | stretch → **fx stretch_text(jjuk)** → (대상 반응) |
| 쭉이 `stretch` → `long_johns` | long_johns flutter → jjuk wet | **jjuk stretch → fx stretch_text(jjuk)** → long_johns flutter → jjuk wet (F-d: 지금은 장대를 안 뻗는데 내복이 날아온다) |
| 묵직이 `stomp` 규칙·반응 전부(시소 규칙 7개 중 쿵 연출이 있는 5개, 까치 규칙 `magpie_stomp_back`, 반응 magpie·nest·hook·basket·long_johns) | stomp → … | stomp → **fx stomp_text(mukjik)** → … |
| 삑삑이 `squeak` | 그대로(`squeak_text`가 이미 바로 뒤) | 그대로 |

- 그대로 두는 것(F-d 거절·가로막힘): `hook_jjuk_pecked`·`hook_jjuk_pecked_magpie`·`magpie_stretch_pecked`(까치가 먼저 쪼음), 삑삑이 `hook`(떨기)·`long_johns`(손가락 까딱)·`basket`(숨기), `seesaw_end_taken_*`(대사만, 쿵 안 함).
- 검사(테스트로 고정, FE): 특기 동사 규칙·반응에서 show에 `[char, 그 캐릭터 특기 연출]`이 있으면 바로 다음 항목은 그 캐릭터의 시그니처 fx다. 시그니처 표는 한 곳에 둔다(캐릭터 정의 옆). 다음 화면에서 빠뜨리지 않게 하려는 검사다.
- 퍼즐 규칙·조건·상태·해법은 바뀌지 않는다. show와 연출 시간만 바뀐다(코어 `step` 결과의 이벤트 목록은 늘어난다).

## 6. 대사 최소 표시 시간

- **처음 보는 대사는 말풍선이 뜬 뒤 1.0초(60틱) 동안 탭으로 넘기지 않는다.** 이미 본 대사(같은 화면에서 **같은 화자가** 같은 글 ID를 한 번 끝까지 띄운 적이 있음)는 지금처럼 0.4초(24틱)다.
- **개정(2026-11-18, #304)**: "본 적 있음"은 화자 + 글 ID로 센다. #303으로 같은 글 ID라도 화자마다 화면 글이 다를 수 있어서다(`<id>.<화자>` 변형). 변형이 없는 공용 대사도 화자가 다르면 처음 보는 대사로 친다(넘기기를 막는 쪽으로 틀림). 재플레이에서 "캐릭터만 바꿔 같은 줄을 다시 볼 때 답답하다"는 말이 나오면 화면에 뜬 글 자체로 세는 쪽을 다시 검토한다.
- 근거: 일본어 한 줄(14자 이하)을 겨우 읽는 시간이 약 1초다. 사장님은 결과를 보려고 다시 눌러서 첫 대사를 못 읽었다(#284 PM 재현). 반대로 같은 실패를 두 번째 볼 때 기다리게 하는 것은 `ui-interaction.md` 5절이 막으려던 것이라, 다시 볼 때는 지금 값을 둔다.
- "본 적 있음"은 세이브하지 않는다(새로고침하면 다시 처음). 게이지 0 리셋으로는 지우지 않는다. 같은 판 안에서는 이미 읽은 글이다.
- 막는 1.0초 동안 들어온 탭은 버린다. 줄 세우지 않는다(`ui-interaction.md` 5절 "줄 선 행동" 위험 그대로).
- 말풍선 전체 길이는 `sayBase` 1.0초 + **화면 글** 글자당 8틱(초당 7.5자), 상한 4.8초(14자 × 2줄 = 28자가 안 잘림)다. **개정(2026-11-18, #304 3번)**: 예전에는 글 ID 문자열 길이를 글자당 4틱으로 셌다(평균 2.5초, 화면 글이 길어도 시간이 안 바뀜). 화면 글(화자 변형 포함, 줄바꿈 자리 U+200B 뺌)로 세고 글자당 8틱으로 올려 평균은 2.6초로 비슷하게 두고, 짧은 줄은 짧게·긴 줄은 길게 했다. 화면 1 대사 93줄: 1.3~3.7초, 14자 2.9초. 1.0초 뒤 넘기기는 그대로라 긴 줄도 기다리지 않아도 된다.
- 클리어 컷 0.4초(#266), 게이지 0 컷, 클리어 카드 0.6초 가드는 그대로다.
- 리스크(읽는 속도, PR #377): 전체 표시 시간으로 보면 14자 2.9초(초당 4.9자), 18자 두 줄 3.4초(초당 5.3자), 최대 28자 4.7초(초당 5.9자)다. 일본어 자막 관례(초당 4자 안팎)보다 빠르다. 실패 연쇄의 템포를 지키려고 고른 값이지만, 일본어를 천천히 읽는 사람은 두 줄 대사를 다 못 읽고 놓칠 수 있다(말풍선이 사라지면 다시 볼 방법이 없다). 재플레이에서 "두 줄 대사를 다 못 읽었다"는 말이 나오면 `sayPerChar`를 10틱으로 올리고, **`sayMax`도 같이** 올린다(28자 = 60 + 10×28 = 340틱 이상). 상한만 그대로 두면 `scene.test.ts` "말풍선 최대 28자는 상한에 잘리지 않는다"가 깨진다. 이 테스트는 그걸 잡으려고 둔 것이다.

## 7. 실패 대사 (ADR-0018 선)

**선: 대사는 "무엇이 모자란지"까지만 말한다(높이, 반대쪽 무게). "누구로, 어디서, 어떻게"(고리에 매달려서, 삑삑이를 태워서)는 말하지 않는다.** 두 번째 대사는 한 단계 더 가도 되지만, 해법 행동을 이름으로 부르지 않는다.

| 키 | 지금 | 바꾼 뒤 | 한국어 원문(`magpie_nest.md` 5절) | 단서 단계 |
|---|---|---|---|---|
| `magpie_nest.nest_too_short` (L09) | 高さが／足りない！ | **ここからじゃ／高さが足りない！** | 여기선 / 높이가 모자라! | "여기선": 서는 자리가 문제라는 것까지. 어디인지는 말하지 않음 |
| `magpie_nest.nest_too_short_again` (L09b) | もっと高い所から／のばせたらなあ… | 그대로 | | "더 높은 곳에서" |
| `magpie_nest.self_smack` (L16) | …痛い。 | **…痛い。／向こう側、空っぽ。** | …아파. / 저쪽, 텅 비었어. | 반대쪽 끝에 아무것도 없다는 관찰만 |
| `magpie_nest.self_smack_again` (L16b) | …わかってて／またやった。 | **…向こう端に／だれか乗ってたら。** | …반대쪽 끝에 / 누가 타 있었으면. | "누가"까지. 누구인지, 그러면 무슨 일이 나는지는 말하지 않음 |
| `magpie_nest.hook_too_short` (L10) | あとちょっと／高ければ！ | 그대로 | | 이미 선 안에서 충분하다 |

- L16은 `fun-checklist.md` C6 "첫 실패는 웃음, 단서는 두 번째"의 예외다. 시소를 혼자 쿵 하는 것은 거의 모든 플레이어가 처음 하는 행동이다. 그런데 규칙 실패라 힌트 카운터에도 안 잡힌다(#257 Luna 단서 점검 빈틈 2). 그래서 첫 대사부터 관찰 한 줄을 붙인다. 웃음(「…痛い。」)은 첫 줄에 그대로 남는다.
- 금칙·길이: 줄마다 14자 이하, 줄머리 금칙은 `ja.json` 테스트를 통과한다. 줄머리 `…`는 예외 2다.
- 성격: 쭉이는 반말 감탄, 묵직이는 `…`로 시작하는 단문(L16b는 혼잣말 가정형), 그대로다.
