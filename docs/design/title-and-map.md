# 메인화면(타이틀)과 깬 판 맵 설계 (#792)

- 작성: 디자이너 Luna, 2026-11-24

- 범위: #792 **1단계**(M2). 화면·입력·글자 자리·그림 비용. 세이브 규칙은 `ui-interaction.md` 11-4절과 `src/core/progress.ts` 그대로이고, 스키마는 바꾸지 않는다.

## 1. 흐름

```
기본 링크(쿼리 없음) → 로딩 → 타이틀
  ├ [つづき]  (세이브 있음 + 다 깨지 않음)  → resumeFrom 화면 → 시작 카드(11-1-1 규칙) → 게임
  ├ [はじめ]  (늘)                         → 세이브 있으면 두 번 누르기(2-3절) → order[0] → 전체 시작 카드 → 게임
  └ [マップ]  (solvedScreens 1개 이상)     → 맵 → 깬 판 → 그 판 처음 → … → 클리어 카드 → 맵

게임 끝 카드(11-5) → [탭] → 타이틀
새로고침 → 타이틀 (게임 안 "타이틀로" 버튼은 1단계에 없다, 2-5절)
```

- 버튼 이름 `つづき`·`はじめ`·`マップ`는 이 문서에서 버튼을 가리키는 **자리 이름**이다. 실제 글은 Kai가 4절 키에 쓴다.
- 쿼리(`?screen=`, `?playtest=1`, 재생·프레임 훅)가 있으면 타이틀을 건너뛰고 지금처럼 바로 게임이다(Theo 메모 3-d). 쿼리는 팀 도구용이라는 기존 결정([기록](../decisions/2026-11-22-default-link-always-latest.md))과 맞는다. 기본 링크는 늘 타이틀부터다.

### 2-1. 버튼이 보이는 조건과 순서

| 세이브 상태 | 버튼 (위 → 아래, 맨 위가 주 버튼) |
|---|---|
| 없음 (첫 방문, Mia QA) | `はじめ` 하나 |
| 있음, 다 깨지 않음 | `つづき` / `はじめ` / `マップ`(깬 판 1개 이상일 때만) |
| 다 깸 (`isAllCleared`) | `マップ` / `はじめ` |

- 버튼 수가 1~3개로 바뀌어도 **맨 위 버튼은 y 132에 고정**하고 아래로 쌓는다. 가운데 정렬로 움직이면 같은 자리를 누르던 손이 다른 버튼을 누른다(진마씨는 같은 판을 여러 번 연다).
- 다 깬 세이브에서 `マップ`가 주 버튼인 이유: 이어 할 곳이 없고, 그 상태의 플레이어가 하고 싶은 건 "그 판 다시 보기"다. `はじめ`를 주 버튼으로 두면 한 번 잘못 눌러 기록을 날릴 위험이 가장 큰 사람(다 깬 사람)에게 그 버튼이 제일 눈에 띈다.
- 키보드: 버튼이라 Tab·Enter·Space가 된다. 타이틀이 뜨면 주 버튼에 초점을 둔다.

### 2-2. `はじめ`를 누르면 무엇이 지워지나 (Theo 메모 3-a)

**① 다 지운다(세이브 `prev = null`).** 깬 판 기록(`solvedScreens`)도 지워져 맵이 빈다. Theo 추천과 같다.

- 고른 이유
  1. **코어 0.** ②(맵은 남기고 `checkpoint`만 처음으로)는 "다시 하기인지"를 `solvedScreens`로 가르는 지금 `saveOnCard` 규칙과 부딪친다. ②로 새로 시작해 첫 판을 깨면 "이미 깬 판을 다시 깸"으로 읽혀 `checkpoint`가 안 움직이고 다음 판으로 못 간다. 고치려면 세이브에 이번 판 모드를 넣어야 하고, 그건 코어 PR(리뷰 2명)이다.
  2. **말이 하나다.** `はじめ` = "처음부터, 아무것도 없는 상태로". 맵에 깬 표시가 남아 있으면 "새로 했는데 왜 깼다고 나오지?"가 된다(Theo 우려 ②).
  3. 그 대신 지우기 전에 확인을 받는다(2-3절). 그리고 다 깬 사람에게는 `マップ`를 주 버튼으로 둬서(2-1절) 잘못 누를 길을 줄인다.
- 다시 볼 조건: 진마씨나 Mia가 "새로 했더니 맵이 없어져서 아쉽다"를 한 번이라도 말하면 ②를 Ben과 다시 본다(코어 PR, 세이브 스키마는 그대로 두는 안부터).

### 2-3. `はじめ` 두 번 누르기 (세이브 있을 때만)

판을 날리는 처음부터 버튼(6-7-2절)과 **같은 방식**으로 한다. 새 모양을 만들지 않는다.

- 세이브가 없으면 한 번 누르면 바로 시작한다(지울 게 없다).
- 세이브가 있으면 첫 누름: 아무것도 지우지 않는다. 버튼이 15번 노랑 바탕 + 잉크 글자로 바뀌고, 확인 줄(2절 표)에 `ui.title.new_confirm`이 뜬다.
- **3초(`RESTART_ARM_MS`와 같은 값)** 안 두 번째 누름: 세이브를 지우고 `order[0]`부터 시작한다. 3초가 지나거나 다른 버튼을 누르면 풀린다.
- 모달 대화상자는 쓰지 않는다(6-7-2와 같은 이유: 장면을 가리고 손이 두 번 더 간다).
- 확인 글은 **맵 기록까지 지워진다는 것**을 말해야 한다(Theo 우려 ①). "처음부터"만 말하면 이어 하기 위치만 바뀐다고 읽힌다.

### 2-4. 시작 카드와 이어지는 규칙

- `はじめ` → `order[0]` 전체 시작 카드(6-2-1).
- `つづき` → 11-1-1 규칙 그대로(첫 화면이면 전체 카드, 아니면 짧은 카드).
- 타이틀 → 게임 사이에도 11-1의 어두워짐 0.3초 → 밝아짐 0.3초를 쓴다. 새 연출 없음.

### 2-5. 게임 안에서 타이틀로 가는 길 (1단계에는 없다)

- 게임 HUD에 "타이틀로" 버튼을 넣지 않는다. 오른쪽 위는 얼굴 칸 끝(x 392)과 처음부터 버튼(x 448) 사이 56px뿐이고, 그 자리는 처음부터 버튼의 `もう一度` 꼬리표 대안(6-7-2 리스크)이 먼저 쓰기로 했다.
- 대신 **새로고침하면 타이틀**이다(기본 링크가 타이틀부터라 따로 만들 것이 없다). 세이브는 카드에서만 쓰므로(11-4) 새로고침해도 잃는 건 지금 판의 진행뿐이다. #767에서 남은 "처음으로 돌아갈 길이 `?screen=`뿐"도 이걸로 풀린다.
- 다시 볼 조건: 진마씨·Mia가 "타이틀/맵으로 가는 길을 못 찾았다"를 말하면, 처음부터 버튼 첫 누름 뒤 꼬리표 자리에 `タイトルへ`를 같이 두는 안부터 본다.

### 3-1. 카드 상태 세 가지

| 상태 | 조건 | 모양 | 누르면 |
|---|---|---|---|
| 깸 | `solvedScreens`에 있음 | 썸네일 원색 + **노란 2px 테두리** + 썸네일 오른쪽 위 깸 도장 16×16 | 그 판을 처음부터 다시 한다(3-4절) |
| 잠금 | 그 밖 | 썸네일 위에 ink 80% + 가운데 `？` 24px(cotton) + lint 1px 테두리. 이름 줄도 lint | 잠금 안내 줄이 뜬다. 판은 열리지 않는다 |
| (그림 전 화면) | 배경 그림이 아직 없음(지금 `laundromat`) | 썸네일 자리를 2번 dusk 한 색으로. 위 두 상태 규칙은 그대로 | 상태 규칙 그대로 |

- **맵에서는 깬 판만 연다.** #792 본문에 "다음 판 하나만 열림"과 "깬 판만 눌린다"(완료 조건)가 같이 있어서 완료 조건 쪽으로 정했다. 아직 안 깬 다음 판은 `つづき`로 간다. 맵에서 다음 판을 열게 하면 그 판을 깼을 때 "이야기 진행"인지 "다시 하기"인지 세이브 규칙이 갈려(2-2절과 같은 문제) 코어를 건드린다.
- 잠긴 카드도 썸네일을 덮을 뿐 지우지 않는다. 어떤 판이 남았는지 모양만 어렴풋이 보여서 "더 있다"가 읽힌다. 덮개가 80%라 단서는 안 읽힌다(스포일러 없음).
- 깸 도장(새 칸 1): HUD 아이콘 시트(`art/ui/hud-icons.mjs`, 20×20 칸)의 다음 칸에 그린다. 모양은 노란 동그라미 안 흰 양말 한 짝(빨래를 하나 되찾았다는 뜻). 글자 도장(`済`)은 쓰지 않는다. 일본어 한자 도장은 시험 채점처럼 읽힌다.
  - 그림: HUD 시트 `stamp` 칸(`public/ui/hud-icons.json` `icons.stamp`, 7번째). 칸은 20×20이고 보이는 것은 칸 (2,2)부터 16×16(외곽선 포함)이다. 그래서 위 표의 16×16 자리 왼쪽 위가 (sx, sy)면 칸을 **(sx − 2, sy − 2)**에 1배로 놓는다. 목업(`title-map-mock.mjs`)이 실제 칸을 이렇게 붙인다.
  - 양말 둘레에 안쪽 ink 선을 두르면 2배에서 줄기 + 머리로 읽혀 음표처럼 보여서, 선 없이 다리 5px·발 덩어리 + 오른쪽 아래 그림자 1px로만 가른다. 발끝은 왼쪽, 목 띠는 red 한 줄.
- 눌렀을 때 반응 없는 카드는 없다. 잠긴 카드도 글이 뜬다(퍼즐 화면의 "반응 없음 = 불공정" 기준을 메뉴에도 적용).

### 3-2. 잠금 안내 글

- 뜻: "아직 이 판에 못 갔다, 이어서 하면 열린다". 어떻게 깨는지·누가 무엇을 하는지는 말하지 않는다(ADR-0018 선, #goblin-general 스포일러 규칙과 같은 이유).
- 2초 뒤 사라진다. 다른 잠긴 카드를 누르면 다시 2초.

### 3-3. 썸네일

- **그 판 시작 상태 장면(배경 + 물건, 캐릭터 없음)을 1:1로 120×68만큼 자른 것.** 줄이지 않는다. 픽셀 그림을 1/4로 줄이면 점이 뭉개져 다른 그림처럼 보인다. 1:1로 자르면 새 칸 0이고 게임 안과 같은 점이다.
- 자르는 왼쪽 위 자리(목업 `THUMB_ORIGIN`, 처음 값): `magpie_nest` (88, 18) 전봇대 꼭대기와 둥지, `park_fountain` (165, 60) 동상 머리·팔과 우산대. Theo 구현 PR 프레임을 보고 Luna가 리뷰에서 고친다. 숫자는 한 곳(맵 설정 파일 하나, 이름은 Theo가 정함)에만 둔다. 화면 데이터(ADR-0065 스키마)에는 넣지 않는다.
- 자르는 자리의 오른쪽 위 20×20에는 그 판의 목표 물건을 두지 않는다(깸 도장 자리).
- `laundromat`은 #764 그림이 들어가는 PR에서 자르는 자리를 같이 정한다.

### 3-4. 맵에서 다시 하기 흐름

```
깬 카드 탭 → 어두워짐 0.3초 → 그 판 처음 상태 → 밝아짐 → 시작 카드(아래) → 게임
  → 클리어 컷 → 클리어 카드(다음 줄이 ui.map.return) → [탭] → 어두워짐 → 맵 (그 카드에 초점)
  마지막 판이면 → 클리어 카드(ui.next 그대로) → 재회 컷 → 끝 카드 → [탭] → 맵
```

- 시작 카드: 11-1-1 규칙 그대로(첫 화면이면 전체, 아니면 짧은 카드). 다시 하는 사람이라도 짧은 카드의 목표 줄은 "이번엔 뭘 하지"를 바로 말해 준다. 전체 카드의 특기·게이지 줄은 첫 화면에서만 나온다.
- 클리어 카드의 다음 줄만 `ui.map.return`(터치)·`ui.map.return_click`(마우스)으로 바꾼다. `タップして次へ`가 뜨는데 맵으로 가면 약속과 다르다.
- **마지막 판(`park_fountain`)은 재회 컷과 끝 카드까지 보여 준다.** 재회 컷은 그 판을 깬 보상이라 다시 할 때도 보고 싶을 자리다. 끝 카드 탭만 타이틀 대신 맵으로 간다.
- 세이브: Theo 메모 1절대로 지금 `saveOnCard` "다시 하기" 경로를 탄다. `checkpoint`는 안 바뀐다(완료 조건 테스트).
- 다시 하는 판 안에서 처음부터 버튼은 그 판 처음으로 간다(6-7-3 그대로). 새로고침하면 타이틀이다.

## 4. 글 키와 글자 수 예산 (일본어는 Kai)

글자 수는 전각 기준. 폭 셈은 ja-text 2절과 같은 방식(14px × 전각 글자 수 + 안쪽 여백)이다.

| 키 | 쓰는 곳 | 예산 | 근거 / 작가에게 |
|---|---|---|---|
| `ui.title.name` | 일본어 제목 | (정해짐) `せんたくもの大脱走` | L3 결정. 작가 글이 아니다. 제목 문자열은 이 키 한 곳에만 두고 `index.html` `<title>`도 빌드 때 여기서 넣는다(ADR-0003 "한 곳에서 관리") |
| `ui.title.name_en` | 영어 로고 | (정해짐) `Laundry Runaways` | 위와 같다 |
| `ui.title.continue` | `つづき` 버튼 | **6자 이하** | 버튼 폭 132 − 여백 16 = 116px, 14px 전각 8자가 끝, 6자 목표 |
| `ui.title.new` | `はじめ` 버튼 | **6자 이하** | 같다. 게임 안 `ui.restart`(`最初から`)와 같은 말이면 안 된다(아래) |
| `ui.title.map` | `マップ` 버튼 | **6자 이하** | 같다 |
| `ui.title.new_confirm` | `はじめ` 첫 누름 뒤 확인 줄 | **20자 이하** | 280px 한 줄. 맵(깬 판) 기록도 지워진다는 것을 꼭 말한다(2-3절). 꼴은 `ui.restart_confirm`(`もう一度押すと…`)과 맞추면 같은 버릇으로 읽힌다 |
| `ui.map.back` | 돌아가기 버튼 | **4자 이하** | 72 − 16 = 56px |
| `ui.map.locked` | 잠금 안내 줄 | **20자 이하** | 3-2절의 뜻. 푸는 법 금지 |
| `ui.map.return` / `ui.map.return_click` | 다시 하기 클리어 카드 다음 줄 | **12자 이하** | `ui.next`(`タップして次へ ▶`)와 같은 자리·같은 꼴 |
| `<id>.map.name` | 판 카드 이름 줄 | **8자 이하** | 카드 안 96px ÷ 12px. 판 별명(장소 이름이 쉽다). 목표 물건·쓰임새를 이름에 넣지 않는다(스포일러) |

- **겹치는 말 정리(6-7-4에서 미뤄 둔 것)**: 타이틀이 생기면 게임 안 처음부터 버튼 `ui.restart`(`最初から`, aria 이름)와 호버·확인 글(`最初からやり直す`)이 타이틀 `はじめ`와 같은 말로 읽힌다. 6-7-4 계획대로 게임 안 쪽을 "이 화면을 다시"로 바꾼다(`やり直す`, 호버 `2回押すとこの画面を最初から` 등. 최종 글은 Kai). **#792 글 PR에서 같이 바꾼다.**
- 버튼 셋은 서로 첫 글자가 달라야 한다. 눈이 첫 글자로 버튼을 가른다.

## 7. 테스트로 고정할 것 (Theo 구현 PR)

1. 세이브 상태 셋에서 버튼 수·순서가 2-1절 표와 같다. 맨 위 버튼 y가 132로 같다.
2. 세이브가 있을 때 `はじめ` 한 번은 아무것도 안 지운다. 3초 안 두 번째에 세이브가 비고 `order[0]`에서 시작한다. 3초 뒤에는 다시 첫 누름이다.
3. 맵: 깬 카드만 판을 연다. 잠긴 카드는 안내 줄만 뜨고 상태가 그대로다.
4. 맵에서 다시 깨도 `checkpoint`가 그대로다(#792 완료 조건). 클리어 카드 다음 줄이 `ui.map.return`이고 탭하면 맵이다.
5. 맵에서 마지막 판을 다시 깨면 재회 컷 → 끝 카드 → 맵이다(타이틀 아님).
6. 쿼리가 있으면 타이틀이 안 뜬다.
